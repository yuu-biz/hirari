# Hirari 製品仕様と技術仕様

- **状態**。草案 0.1（2026-11-02）
- **対象**。Android 9（API 28）以上のスマートフォンとタブレット
- **表記**。(要検証) は推測または計測が必要な記述を表す。「既定」はユーザーが変えられる初期値を表す。「初期目標」は計測で見直す性能値を表す。

## 1. 概要

### 1.1 アプリの目的

本アプリは、自分でスキャンした本（主に漫画）を読むための Android アプリである。画像を収めた書庫（ZIP、RAR、7z、tar）、画像を入れたフォルダ、画像だけの PDF を開く。プレーンテキストと青空文庫記法のテキストを縦書きで読むリーダーも持つ。

価値の中心は読書体験であり、次の 4 点を製品の約束とする。

1. めくりが即座である。先読み済みのページは、入力の次のフレームで画面に出る。
2. 片手で操作できる。めくり、ページ移動、コマンドの呼び出しは親指 1 本で完結する。
3. 見開きが正しく組まれる。横長のページは単独で出し、組がずれたら 1 回の操作で直せる。
4. 壊れた入力で落ちない。読めないページはその位置にエラーとして出し、前後のページは普通に読める。

### 1.2 想定ユーザー

| ユーザー | 使い方 | 重視すること |
|---|---|---|
| 自炊した蔵書を多く持つ人 | 端末や SD カードに数百から数千冊の書庫を置く | 一覧の速さ、既読管理、続きから読めること |
| NAS に蔵書を置く人 | 家庭内 LAN の SMB 共有から、コピーせずに読む | 接続の安定、待ち時間の短さ |
| 寝転んで長時間読む人 | 片手持ちで、親指だけで操作する | 誤操作の少なさ、めくりの速さ、画面の向きの固定 |
| 青空文庫の読者 | テキストを縦書きで読む | ルビ、縦中横、読みやすい組版 |

### 1.3 目標

| ID | 目標 | 確かめ方 |
|---|---|---|
| G1 | 先読み済みページのめくりが 1 フレーム以内に描画を始める | 5 章の計測手順 |
| G2 | 片手操作だけで、めくり、ページ移動、組ずらし、しおり追加ができる | 4 章の操作表を片手で一巡する手動試験 |
| G3 | どんな入力ファイルでも、エラーの出る経路ではアプリが終了しない | 6 章のコーパス試験と fuzz |
| G4 | 設定を約 60 項目に絞り、どの項目も読書の流れに役立つ | 4.10 節の設定表 |
| G5 | 利用者が登録した SMB 以外にネットワーク通信をしない | 7 章、マニフェストと依存の審査 |
| G6 | 依存ライブラリはすべて寛容なライセンスで、記録されている | 8.5 節の表と CI の検査 |

### 1.4 非目標

次のものは作らない。将来の検討対象になるものは 10 章に挙げる。

- オンラインの漫画配信サービス、カタログ、ストアとの連携。
- DRM 付きの電子書籍。
- 画像や書庫の編集。ページの並べ替え、書庫の作成、画像を加工して保存することを含む。ファイルの削除と名前変更だけは設定で許可できる。
- リフロー型 EPUB と HTML 本文の表示。
- 文字を持つ PDF の文字選択、検索、注釈。
- 分割書庫（マルチボリューム）と、書庫の中に入った書庫。
- クラウドストレージ各社の API を直接呼ぶこと。クラウドは Storage Access Framework（SAF）のドキュメントプロバイダ経由でだけ扱う。
- 利用状況の収集、広告、アカウント登録。

## 2. 用語とドメインモデル

### 2.1 用語

この文書は次の語を 1 つの意味でだけ使う。

| 用語 | 意味 |
|---|---|
| 場所 | 本を探す起点。SAF で許可を得たフォルダか、SMB の共有 |
| 本 | 1 つの書庫、画像フォルダ、PDF、またはテキストファイル |
| ページ | 本の中の 1 枚の画像。PDF では 1 ページ |
| 横長ページ | 幅が高さより大きいページ。2.3 節で定義する |
| ビュー | 画面に一度に出す単位。単ページ、2 ページの組、横長ページの半分のいずれか |
| アンカー | ビューの組み方を決める起点のページ。アンカーのページは必ずビューの先頭になる |
| 組ずらし | アンカーを 1 ページ前後に動かして、組み合わせを 1 枚ずらす操作 |
| 綴じ方向 | 右綴じ（右から左へ読む）か左綴じ（左から右へ読む）か |
| 停止点 | 画面より大きいビューを読み進めるときに止まる表示位置 |
| めくり領域 | リーダー画面のうち、コマンドバーとページバーを除いた部分 |
| コマンドバー | リーダー画面の上端の帯。押して滑らせて離す 1 動作でコマンドを実行する |
| ページバー | リーダー画面の下端の帯。横に滑らせてページを選ぶ |
| 端引き | 画像の端を越えて引っ張り、離してめくる操作 |
| ルーペ | 長押しした位置を拡大して見せる小窓 |
| 本ごとの設定 | 1 冊だけに効く設定の上書き。2.9 節で定義する |
| 読書状態 | 未読、読みかけ、既読のいずれか |

### 2.3 ページ

```kotlin
enum class ImageType { Jpeg, Png, WebP, Gif, Bmp, Heif, Avif, JpegXl, PdfPage }

data class PageEntry(
	val index: Int, // 表示順。並べ替えの後の番号
	val entryIndex: Int, // 書庫内の格納順
	val rawName: ByteArray, // 文字コード判定前のバイト列
	val name: String, // 判定後の名前。文字コードを変えると rawName から作り直す
	val declaredSize: Long?, // 書庫が宣言する展開後の大きさ。宣言がなければ null。上限の判定にだけ使い、信用しない
	val sniffed: ImageType?, // 先頭バイトを読むまで null
)

sealed interface PageShape {
	data object Unknown : PageShape
	data class Known(val width: Int, val height: Int) : PageShape {
		val isWide: Boolean get() = width > height
	}
}
```

- 横長の基準は「幅が高さより大きい」である。単ページの縦横比を r とすると見開きは 2r になり、両者の対数上の中間は r√2 である。漫画の r は 0.7 前後なので中間は 1.0 前後になり、幅と高さの比較がそのまま基準になる。
- 正方形に近いページ（比が 0.95〜1.05）の扱いは実データで確かめる (要検証)。
- 圧縮後の大きさは持たない。libarchive のエントリの API が返さないためである。

### 2.4 ページの読み込み結果

```kotlin
sealed interface PageResult {
	data class Ready(val image: PreparedImage) : PageResult
	data class Failed(val reason: FailureReason, val retryable: Boolean) : PageResult
	data class Unsupported(val kind: UnsupportedKind) : PageResult
}

enum class FailureReason { Corrupt, Truncated, ReadError, ConnectionLost, Timeout }

sealed interface UnsupportedKind {
	data object Encrypted : UnsupportedKind
	data class Compression(val method: String) : UnsupportedKind
	data class ImageFeature(val detail: String) : UnsupportedKind // 例 "12 ビット JPEG"
	data class TooLarge(val width: Int, val height: Int, val bytes: Long) : UnsupportedKind
	data object NotAnImage : UnsupportedKind
}

sealed interface PreparedImage {
	val shape: PageShape.Known
	data class Whole(val bitmap: Bitmap, override val shape: PageShape.Known) : PreparedImage
	data class Tiled(val source: TileSource, override val shape: PageShape.Known) : PreparedImage
}
```

- 例外、デコーダのエラー、書庫のエラーはすべて読み込み層の境界で `PageResult` に変換する。リーダーは `PageResult` だけを見る。
- `retryable` は、通信切断や一時的な読み込み失敗のときに真になる。リーダーはそのとき再試行の操作を出す。
- `PreparedImage` は `Bitmap` を持つので `:core:image` に置く。`:core:model` の `PageResult` は画像の型を引数に取る `PageResult<T>` とし、`Ready<T>` が画像を持つ。
- `PreparedImage.shape` は、EXIF の回転を適用した後の元の画像の寸法である。縮小した `Bitmap` の寸法ではない。
- 書庫のエントリが展開サイズの上限（3.7 節）を超えたときは、画像の寸法が分からないので `TooLarge(0, 0, バイト数)` にする。
- 分類できない例外は `Failed(ReadError, retryable = true)` にする。デコーダの `DecodeException` は、入力が途中で終わったものを `Truncated`、入力元の例外を `ReadError`、それ以外を `Corrupt` にする。
- デコーダが画像を返したものは、データが途中で切れていても `Ready` にする。途中で切れたプログレッシブ JPEG は、API 37 のエミュレータの `ImageDecoder` が例外を出さずに届いた走査までの画質で返し、API 28 のエミュレータでは壊れたデータとして例外を出すので `Failed(Corrupt)` になる（コーパスで確かめた）。M1 はこの差をそのまま受け入れ、コーパスの目録には両方を許す結果として書く。切れたことを自前で判定するかと、表示で知らせるかは 10 章の Q20 で決める。

本を開く結果は、開いた本か、開けなかった理由（文書がない、許可がない、複製の空きがない、壊れている、途中で切れている、読み込みの失敗）のどちらかである。開いた本は、ページの一覧、書庫の一覧が途中で止まった理由、ページを読む操作、ページの形だけを読む操作を持つ。どの操作も `PageResult` を返し、取り消し以外の例外を投げない。

### 2.5 綴じ方向とビュー

```kotlin
enum class ReadingDirection { RightToLeft, LeftToRight }

enum class LayoutMode { Single, Spread, SplitWide, Auto }

data class LayoutSettings(
	val mode: LayoutMode, // Auto は呼び出し側で画面の向きから Spread か SplitWide に解決する
	val direction: ReadingDirection,
	val coverAlone: Boolean,
)

enum class HalfPart { First, Second } // 読む順で先の半分が First

sealed interface PageView {
	val pages: List<Int>
	data class One(val page: Int) : PageView
	data class Two(val earlier: Int, val later: Int) : PageView // 画面上の左右は綴じ方向で決める
	data class Half(val page: Int, val part: HalfPart) : PageView
}

fun layoutViews(
	pageCount: Int,
	shape: (Int) -> PageShape,
	settings: LayoutSettings,
	anchor: Int,
): List<PageView>
```

`layoutViews` は副作用を持たない純粋関数である。同じ引数には同じ結果を返す。

各モードの組み方は次のとおり。

| モード | 縦長ページ | 横長ページ |
|---|---|---|
| `Single` | 1 枚で 1 ビュー | 1 枚で 1 ビュー |
| `Spread` | 隣の縦長ページと組む | 単独で 1 ビュー |
| `SplitWide` | 1 枚で 1 ビュー | 半分ずつ 2 ビュー。読む順で先の半分を先に出す |
| `Auto` | 画面が横長なら `Spread`、縦長なら `SplitWide` として扱う | 同左 |

`Spread` の組み方の規則は次のとおり。

1. 形が `Unknown` のページは縦長として扱う。
2. 横長ページは常に単独のビューになる。
3. `coverAlone` が真なら、先頭ページ（0 番）は常に単独のビューになる。
4. アンカー a から後ろへ向かって、貪欲に組む。a と a+1 がともに縦長なら `Two(a, a+1)` にして a+2 へ進む。そうでなければ `One(a)` にして a+1 へ進む。
5. a-1 から先頭へ向かって、同じく貪欲に組む。a-2 と a-1 がともに縦長なら `Two(a-2, a-1)` にする。そうでなければ `One(a-1)` にする。
6. `Two` の画面上の配置は綴じ方向で決める。右綴じでは `earlier` を右に、`later` を左に置く。

アンカーの動かし方は次のとおり。

| 操作 | アンカー |
|---|---|
| 本を開く | 保存されたビューの先頭ページ。初めてなら 0 |
| 順にめくる（進む、戻る） | 変えない |
| ページを指定して移動する（ページバー、しおり、書庫内一覧） | 移動先のページ |
| 組ずらし（進む向き） | 現在のビューの先頭ページ + 1 |
| 組ずらし（戻る向き） | 現在のビューの先頭ページ − 1 |
| 組み方や画面の向きが変わる | 現在のビューの先頭ページ |

操作の後に表示するビューは次のとおり決める。

- 順めくりは、隣のビューに移る。本の端では何もしない。
- ページの指定は、アンカーで始まるビューにする。
- 組ずらしと、組み方や画面の向きの変化では、今のビューが組み直した後にも残っていればそのまま表示する。残っていなければ、新しいアンカーで始まるビューにする。横長ページの単独のビューで組ずらしをしても表示が変わらないのは、この規則による。
- ページの形が分かって組み直したときは、今のビューが残っていればそのまま表示する。残っていなければ、今のビューがアンカーのビューかそれより後ろならその先頭のページを含む最初のビューに、アンカーより前ならその末尾のページを含む最後のビューにする。戻る向きに読んでいて横長ページが分かったときに、アンカーの側に隣り合うビューを出すためである。

アンカーを順めくりで変えないので、進んでから戻ると必ず同じビューに戻る。毎回現在ページを起点に組み直すと、横長ページの手前に奇数枚の縦長ページがある区間で、戻ったときに組が変わってしまう。この性質を不変条件として試験する。

組み方の例を次に示す。T は縦長、W は横長のページを表す。ビューは読む順に並べる。

| ページの並び | 設定とアンカー | ビュー |
|---|---|---|
| T T T W T T（0〜5） | `Spread`、表紙単独なし、アンカー 0 | [0,1] [2] [3] [4,5] |
| 同上 | 表紙単独あり、アンカー 0 | [0] [1,2] [3] [4,5] |
| 同上 | 表紙単独なし、アンカー 1（組ずらしの後） | [0] [1,2] [3] [4,5] |
| T T T T T（0〜4） | 表紙単独なし、アンカー 0 | [0,1] [2,3] [4]。最終ページが余れば単独にする |
| 同上 | アンカー 3（ページバーで 3 へ移動） | [0] [1,2] [3,4] |
| W T T | `SplitWide`、右綴じ、アンカー 0 | [0 の右半分] [0 の左半分] [1] [2] |
| W T T | `SplitWide`、左綴じ、アンカー 0 | [0 の左半分] [0 の右半分] [1] [2] |
| T T ?（2 は未読み込み） | アンカー 0 | [0,1] [2 は縦長と仮定]。2 が横長と分かれば、表示する前に [2] 単独に直す |

端での扱いは次のとおり。

- 組ずらしで新しいアンカーが 0 未満か最終ページを超えるときは、範囲内に丸める。丸めた結果が今のアンカーと同じなら何もしない。
- 現在のビューが横長ページの単独のときに進む向きへ組ずらしをすると、次のページから組み直す。横長ページ自体の表示は変わらない。
- `Half` のビューで組ずらしをしても、組み方は変わらない。半分の分割は組の対象にならないためである。`Spread` 以外の組み方（`Auto` は解決した後の組み方）では、組ずらしは何もしない。組がないのにアンカーだけを動かすと、まだ表示していないページがアンカーになり、戻ってから進んだときに同じビューに戻らなくなるためである。
- 1 ページしかない本は、どのモードでも `One(0)` になる（横長で `SplitWide` なら 2 つの `Half`）。

不変条件（プロパティテストで確かめる）:

- すべてのページは、ちょうど 1 つのビューに入る。`Half` は 2 つで 1 ページを覆う。
- ビューの並びはページ番号の順を保つ。
- アンカーのページは、あるビューの先頭にある。
- 現在のビューより前にあり、すでに表示したページの形は既知である。したがって、先のページの形が判明しても、現在のビューは変わらない。
- 先読みは、次のビューを用意する前に、そのビューに入りうるページの形を先に読む（5.3 節）。

### 2.6 停止点

```kotlin
enum class StopOrder { RowsFirst, ColumnsFirst }

fun scrollStops(
	content: RectF, // ビュー内のページの矩形。Two では 1 ページずつ渡す
	viewport: SizeF,
	maxStep: Float, // 1 回の移動量の上限。画面の大きさに対する比
	order: StopOrder,
	direction: ReadingDirection,
): List<Offset>
```

停止点の規則は次のとおり。

1. 軸ごとに、はみ出し量 `overflow = content − viewport` を求める。はみ出さない軸は中央の 1 点だけにする。
2. はみ出す軸は `steps = ceil(overflow / (viewport × maxStep))` 回に等分し、両端を含む `steps + 1` 点を置く。等分なので、どの移動も同じ距離になる。
3. 右綴じでは横の点を右端から並べ、左綴じでは左端から並べる。縦は常に上から並べる。
4. `RowsFirst` は横に進んでから 1 段下がる。`ColumnsFirst` は縦に進んでから横へ移る。
5. `Two` のビューでは、読む順で先のページの停止点を出し切ってから、次のページに移る。
6. 前のビューへ戻ったときは、そのビューの最後の停止点から始める。進んだときは最初の停止点から始める。

- `:core:model` では `RectF`、`SizeF`、`Offset` の代わりに、`Float` を持つ `Rect`、`Size`、`Point` を使う。
- 停止点は、`content` と同じ座標系での画面の左上の位置である。はみ出さない軸の 1 点は、画面の中央と内容の中央を合わせる位置になる。
- `steps` は、ceil の前に 0.001 を引いてから求める。0.7 のような比は浮動小数で正確に表せず、ちょうど割り切れる長さで停止点が 1 つ増えるためである。

### 2.7 読書位置と読書状態

```kotlin
sealed interface ReadingPosition {
	data class Image(val viewStart: Int, val pageCount: Int) : ReadingPosition // 開くとき viewStart をアンカーにする
	data class Text(val charOffset: Long, val totalChars: Long) : ReadingPosition
}

enum class ReadState { Unread, Reading, Read }

data class BookProgress(
	val book: BookId,
	val state: ReadState,
	val position: ReadingPosition?,
	val updatedAt: Instant,
)
```

- 本を開くと `Reading` になる。最後のビュー（テキストでは最後のページ）を表示すると `Read` になる。
- 2 ページの組では、最終ページを含む組を表示した時点で `Read` になる。
- `Read` の本を開くと、保存された位置（多くは最後のビュー）から始める。4.8 節の「本の端での動作」で「最初から読む」を選べる。
- 拡大率とスクロール位置は保存しない。開き直すと拡大モードの倍率で、ビューの最初の停止点から表示する。
- 位置はビューが変わるたびに保存する。書き込みは 500 ms ごとにまとめ、`onStop` で必ず書き出す。書き込みは、前の書き込みのあとの最初の変化から 500 ms の間をまとめ、本ごとに最後の位置を書く。失敗した位置は捨てず、次の書き込みに回す。
- テキストの位置は文字の通し番号で持つ。文字の大きさや画面の向きを変えても同じ文章から再開できる。
- 文字コードを変えて並び順が変わったときは、`entryIndex` を介して位置を新しい番号に置き直す。

### 2.8 しおりと履歴

```kotlin
data class Bookmark(val id: Long, val book: BookId, val position: ReadingPosition, val label: String, val createdAt: Instant)
data class HistoryEntry(val book: BookId, val openedAt: Instant)
```

- しおりの既定の名前は、画像の本では `p. 12`、テキストでは `12%` とする。
- 履歴は本ごとに 1 件で、開くたびに日時を更新する。件数の上限を超えたら古いものから消す。

### 2.9 本ごとの設定

```kotlin
data class BookOverrides(
	val direction: ReadingDirection? = null,
	val layoutMode: LayoutMode? = null,
	val coverAlone: Boolean? = null,
	val scaleMode: ScaleMode? = null,
	val trim: TrimStrength? = null,
	val rotation: Rotation? = null, // 0, 90, 180, 270 度
	val reverseOrder: Boolean? = null,
	val nameCharset: Charset? = null,
	val adjust: ImageAdjust? = null,
)
```

- `null` は全体の設定に従うことを表す。
- `ScaleMode`、`TrimStrength`、`ImageAdjust` の値は 4.10 節の `scaleMode`、`trimStrength`、`adjust*` の範囲と同じである。`Rotation` は 0、90、180、270 度の 4 値の列挙とする。
- リーダー内で変えた表示設定は、その本の上書きとして保存する。リーダーのメニューにある **既定にする** で、上書きを全体の設定に移す。
- この仕組みで、リーダー内の一時的な切り替えと、初期値として保存する操作を 1 つにまとめる。

## 3. 対応形式と入力の扱い

### 3.1 入力元

| 入力元 | 取得方法 | ランダムアクセス | 備考 |
|---|---|---|---|
| 端末内のフォルダ | `ACTION_OPEN_DOCUMENT_TREE` で許可を得て、永続許可を保存する | `ParcelFileDescriptor` と `FileChannel` で任意位置を読む | ストレージ権限は要求しない |
| クラウドなどのドキュメントプロバイダ | 同上 | プロバイダしだい。シークできない場合はキャッシュに複製してから開く | 複製は空き容量の範囲で行い、超えるときは開かずに理由を出す |
| 他アプリから渡されたファイル | `ACTION_VIEW` の content URI | 同上 | 4.11 節 |
| SMB 2 と SMB 3 の共有 | smbj で直接接続する | `read(offset, buffer)` で任意位置を読む | SMB 1 には接続しない |

すべての入力元は次の 1 つの型で読む。読み込み層より上は入力元の違いを知らない。

```kotlin
interface ByteSource : Closeable {
	val size: Long
	fun read(offset: Long, dst: ByteBuffer): Int // 呼んだスレッドを止める。-1 は終端
}
```

- `read` は中断関数（`suspend`）にしない。libarchive が JNI のコールバックの中から、書庫のセッションのスレッドで呼ぶためである。取り消しはセッションの取り消しフラグで伝える（8.3 節）。SMB の同時に読む数の上限は、SMB の実装の中で守る。
- SAF の文書は `ContentResolver.openFileDescriptor` で開く。`ParcelFileDescriptor.getStatSize` が負（パイプかソケット）ならシークできないとみなし、`cacheDir/copy/` に複製する。複製は開いた直後にファイル名を消すので、`ByteSource` を閉じると消える。複製で空き容量が 64 MB を切るときは、そこで止めて開かない (要検証。残す量)。
- フォルダの一覧は、`DocumentsContract.buildChildDocumentsUriUsingTree` への 1 回のクエリで、文書 ID、表示名、MIME タイプ、大きさを得る。ファイルごとの Binder 呼び出しはしない。

### 3.2 形式の判定

形式は先頭バイト（マジックバイト）で決める。拡張子は、一覧に並べる候補を選ぶことと、判定できなかったときの表示名にだけ使う。

| 形式 | 判定に使うバイト | 位置 |
|---|---|---|
| ZIP | `50 4B 03 04`、空の書庫は `50 4B 05 06` | 先頭。自己解凍形式のように前置データがある場合は末尾の終端レコードから逆算する |
| RAR 4 | `52 61 72 21 1A 07 00` | 先頭 |
| RAR 5 | `52 61 72 21 1A 07 01 00` | 先頭 |
| 7z | `37 7A BC AF 27 1C` | 先頭 |
| tar | `ustar` | 257 バイト目 |
| PDF | `%PDF-` | 先頭 1024 バイト以内 |
| JPEG | `FF D8 FF` | 先頭 |
| PNG | `89 50 4E 47 0D 0A 1A 0A` | 先頭 |
| WebP | `RIFF` と、8 バイト目からの `WEBP` | 先頭 |
| GIF | `GIF87a`、`GIF89a` | 先頭 |
| BMP | `BM` と、妥当なヘッダ長 | 先頭 |
| HEIF、HEIC | `ftyp` ボックスのブランドが `heic`、`heix`、`hevc`、`heim`、`heis`、`mif1`、`msf1` | 4 バイト目 |
| AVIF | `ftyp` ボックスのブランドが `avif`、`avis` | 4 バイト目 |
| JPEG XL | `FF 0A`（コードストリーム）、`00 00 00 0C 4A 58 4C 20 0D 0A 87 0A`（コンテナ） | 先頭 |
| テキスト | 上のどれにも当たらず、先頭 4 KB に NUL がない（UTF-16 の BOM がある場合を除く） | 先頭 |

- `ftyp` のブランドは major brand と compatible brands の両方を見る。`mif1` だけを持つファイルは、中の画像アイテムの種類で HEIF か AVIF かを決める。
- 拡張子と中身が違うときは中身に従う。`.jpg` という名前の PNG は PNG として読む。

### 3.3 書庫の読み込み

書庫の読み込みには libarchive を JNI 経由で使う。libarchive にはファイルパスを渡さず、`ByteSource` を読むコールバック（read、seek、skip）を渡す。端末内のファイルにも `archive_read_open_fd` の経路は設けない。API 37 のエミュレータで、300 エントリで 92 MB の ZIP について、開いて索引を作る時間、全エントリを読む時間、最後のエントリだけを読む時間を両方の経路で 7 回ずつ交互に測り、中央値に差が見えなかったためである（全エントリを読む時間の中央値はコールバックが 1,891 ms、`archive_read_open_fd` が 1,907 ms。実機では未計測）。

| 形式 | 必須の対応 | 扱い |
|---|---|---|
| ZIP | ZIP64、データディスクリプタ（汎用フラグの bit 3）、長いコメント、前置データ、UTF-8 フラグ（bit 11）、無圧縮と Deflate | 末尾 16 KB に終端レコードがあれば、中央ディレクトリを読む方式で開く。終端レコードがそれより前にある（コメントが 16 KB を超える）か、切れて無いときは、ローカルヘッダを先頭から順に読む方式で開く（libarchive 3.8.11 のソースで確かめた）。無圧縮と Deflate 以外の方式はビルドしていないので、`Unsupported(Compression)` にする |
| RAR 4 | 通常と solid | (要検証) libarchive の対応範囲を M3 の最初に確かめる |
| RAR 5 | 通常と solid | (要検証) 同上 |
| 7z | LZMA、LZMA2、PPMd、BCJ、Deflate、BZip2 | solid ブロックは先頭から順に展開する |
| tar | 無圧縮、gzip、xz、zstd | |
| 暗号化された書庫 | | 3.8 節 |
| 分割書庫 | | 非目標。開いたときに「分割された書庫には対応していません」と出す |

libarchive は順に読む形の API を持つ。任意のエントリを開く費用は形式で大きく違うので、次の費用モデルで設計する。

| 形式 | N 番目のエントリを開く費用 | 方針 |
|---|---|---|
| ZIP | N より前のローカルヘッダを読み（データはスキップで飛ばす）、展開 1 件。libarchive にエントリへ直接飛ぶ API はない | 開くときに全エントリの索引を作る。今より後のエントリへは前に進み、前のエントリへはハンドルを開き直して中央ディレクトリから読み直す |
| 非 solid の RAR、tar | 前のエントリのヘッダを順に読み、データはシークで飛ばす | 索引を作り、ハンドルの再オープンとスキップで移動する |
| solid の RAR、7z の solid ブロック | N より前の全データを展開する | 展開キャッシュを使う（下記） |
| 画像フォルダ | ファイルを 1 つ開く | 直接開く |
| PDF | ページを 1 つ描く | 3.9 節 |

展開キャッシュ（solid 書庫用）の規則は次のとおり。

- 本を開くと、バックグラウンドで先頭から順に展開し、各エントリをキャッシュディレクトリのファイルに書き出す。
- リーダーが求めるページがまだ展開されていなければ、そのページまで展開が進むのを待つ。待つ間は読み込み中の表示を出す。
- キャッシュの上限は、空き容量の 10% と 2 GB の小さい方にする (要検証)。上限を超えたら、現在ページから遠いものから消す。
- 本を閉じてから 24 時間たったキャッシュは消す。

書庫ごとに 1 つの `ArchiveSession` を作る。セッションは libarchive のハンドルを専有し、呼び出しは直列にする。サムネイル生成はリーダーと別のセッションを使う。ネイティブ側にプロセス全体で共有する状態を持たない。

- セッションは `ByteSource` を所有し、セッションを閉じるとき（開けなかったときはその場で）閉じる。
- シークかスキップの直後の読み込みは 4 KB だけを求め、続けて読むときは 64 KB を求める。前に進むときに読むローカルヘッダ 1 つあたりの量を抑えるためである。
- 開くときは、読めたところまでのエントリを索引にする。ヘッダが読めなくなったら、そこで一覧を止め、理由を索引に残す。
- libarchive のエラーは次のように分ける。`ByteSource` の読み込みが例外を投げたら `ReadError`、libarchive が終端より先を求めたら `Truncated`、それ以外は `Corrupt`。暗号化の印があるエントリは `Encrypted`、展開できない方式は `Compression(方式)` として、データを読まずに返す。
- 展開した量は実際に書き出した量で数え、上限（3.7 節）を超えるブロックが来たら止めて `TooLarge` にする。宣言サイズが上限を超えるエントリは読まずに `TooLarge` にする。

### 3.4 エントリ名の文字コード

エントリ名は libarchive が返すバイト列を `rawName` として受け取り、Kotlin 側で文字列にする。libarchive 3.8.11 は ZIP の名前を次のように返す（ソースで確かめ、API 37 のエミュレータでコーパスを読んで確かめた）。

- UTF-8 フラグのない名前は、バイト列のまま返す。CP932 の 2 バイト目が `\` と同じ 0x5C でも、区切りに変えない。
- UTF-8 フラグの立った名前と、Info-ZIP の Unicode Path 拡張フィールド（0x7075）の名前は、UTF-8 として NFC に正規化してから返す。正しい UTF-8 でなければ名前を返さない。
- この変換は公開の API では止められず、UTF-8 フラグも公開の API では分からない。libarchive に手を入れないため、この形をそのまま受け入れる。名前が返らないエントリは、`rawName` を空にし、名前を U+FFFD 1 文字にする。

判定は書庫単位で行い、エントリごとに変えない。判定の順は次のとおり。

1. すべての名前が正しい UTF-8 なら UTF-8 にする。UTF-8 フラグの立った名前は libarchive が UTF-8 にして返すので、ここに入る。ASCII だけの名前もここに入る。CP932 の実装には 0x5C を円記号にするものがあり、ASCII を CP932 で読むと同じ文字になるとは限らないためである。
2. すべての名前が正しい CP932 なら CP932 にする。
3. それ以外は、名前をつないだバイト列を `android.icu.text.CharsetDetector` にかけ、日本語を優先する候補から最も確からしいものを選ぶ。
4. 確からしさが低いときは、設定「判定できないときの文字コード」に従う。

- M1 では 3 を飛ばし、4 の設定の既定値の CP932 にする。3 は M3 で加える。
- UTF-8 フラグの立った名前とフラグのない CP932 の名前が混ざった書庫は、1 にも 2 にも当たらず、フラグの立った名前が化ける。中央ディレクトリから名前とフラグを直接読むかは M3 で決める (要検証)。

- 書庫内一覧とリーダーのメニューから、本ごとに文字コードを手動で選び直せる。選び直すと `rawName` から名前を作り直し、並べ直す。
- 正しく変換できないバイトは U+FFFD に置き換えて表示し、読み込み自体は続ける。

### 3.5 ページの一覧と並び順

ページの一覧は本を開いたときに一度だけ作り、読んでいる間は増減させない。

- 画像の拡張子を持つエントリを一覧に入れる。
- 拡張子がないか未知のエントリは、非 solid の書庫では先頭のバイトを読んで画像なら入れる。solid の書庫では入れない (要検証。費用と取りこぼしを実データで比べる)。書庫のセッションはエントリを丸ごと読むので、ZIP では本を開くときにそのエントリを展開サイズの上限まで読む。画像フォルダではファイルの先頭 32 バイトだけを読む。
- 次のものは入れない。ディレクトリ、`__MACOSX/` の下、パスのどこかの部分が `.` で始まるもの、`Thumbs.db`、`desktop.ini`、テキストや目録の拡張子（`.txt`、`.nfo`、`.xml`、`.sfv`、`.md5`、`.url`）。拡張子と名前は大文字と小文字を区別しない。
- 画像の拡張子は `.jpg`、`.jpeg`、`.jpe`、`.jfif`、`.png`、`.webp`、`.gif`、`.bmp`、`.heic`、`.heif`、`.avif`、`.jxl` である。
- テキストのエントリは書庫内一覧にだけ出し、テキストリーダーで開く。

並び順は既定で自然順にする。自然順の比較規則は次のとおり。

1. 名前を Unicode NFKC で正規化し、大文字と小文字を区別しない。全角の数字は半角の数字として扱う。
2. パスをフォルダの区切り（`/` と `\`）で分け、フォルダから順に比べる。
3. 各部分を数字の並びとそれ以外に分ける。数字の並びは数値として比べ、等しければ桁の少ない方を先にする（`1` は `01` より先）。数字の並びは、ほかの文字との比較では `0` の位置に並ぶ。
4. 漢数字の並び（〇、一〜九、十、百、千を組み合わせたもの）は数値として比べる。「第十二巻」は「第三巻」より後になる。十、百、千を含まない並びは位取りで読む（「二〇二四」は 2024）。
5. 巻の区分を表す 1 文字は、同じ前置部分を持つ名前どうしで「上、前、中、後、下、短、外」の順に並べる。「短」は短編集、「外」は外伝を表し、本編の後に置く。これらの文字は、ほかの文字との比較ではまとめて「上」の位置に並ぶ。文字ごとの符号位置で比べると、区分の順と矛盾して並べ替えの順序が定まらないためである。
6. 以上で決まらなければ、変換前のバイト列で比べる。大文字と小文字は、大文字にしてから小文字にして同一視する（`Σ` と語末の `ς` を同じに扱うため）。バイト列も同じなら、書庫内の格納順で並べる。

**例**。`1.jpg`、`2.jpg`、`10.jpg` はこの順に並ぶ。`作品 上.zip`、`作品 中.zip`、`作品 下.zip`、`作品 外伝.zip` もこの順に並ぶ。

本ごとの設定 `reverseOrder` で並びを逆にできる。設定「書庫内の並び」で格納順も選べる。

### 3.6 画像形式

| 形式 | API 28〜30 | API 31 以上 | 必須の対応 |
|---|---|---|---|
| JPEG | `ImageDecoder` | 同左 | ベースライン、プログレッシブ、グレースケール、CMYK と YCCK、EXIF の回転、ICC プロファイル |
| PNG | `ImageDecoder` | 同左 | すべてのカラータイプ（パレットと tRNS を含む）、16 ビット、インターレース |
| WebP | `ImageDecoder` | 同左 | 非可逆、可逆、アルファ。アニメーションの扱いは Q3 |
| GIF | `ImageDecoder` | 同左 | アニメーションの扱いは Q3 |
| BMP | `ImageDecoder` | 同左 | 1、4、8、24、32 ビット |
| HEIF、HEIC | `ImageDecoder` | 同左 | 端末のハードウェアデコーダに依存する (要検証)。デコードできない端末では `Unsupported(ImageFeature)` |
| AVIF | libavif と dav1d（同梱する場合） | `ImageDecoder` (要検証。API 31〜33 の対応範囲) | Q6 |
| JPEG XL | libjxl | 同左 | 静止画。アニメーションは先頭フレーム |

- M1 で読むのは JPEG、PNG、WebP である。ほかの形式は判定だけを行い、対応するまで `Unsupported(ImageFeature(形式名))` にする。
- 12 ビット JPEG とロスレス JPEG は、プラットフォームが読めなければ `Unsupported(ImageFeature)` にする (要検証)。
- アルファを持つ画像は、リーダーの背景色の上に合成する。
- 色は sRGB に変換して表示する。
- `ImageDecoder` は EXIF の回転を自動で適用する。`BitmapRegionDecoder` は適用しないので、タイル経路では回転を自前で適用する。

### 3.7 デコードの計画と上限

画像は次の段階で読む。各段階の間で取り消しを確かめる。

1. 判定する。バイト列の先頭で形式を決める。書庫のセッションはエントリを丸ごと読むので、書庫ではエントリを読み終えたバイト列で判定する。任意の位置を読める入力元（画像フォルダなど）では、先頭 32 バイトだけを読んで判定してよい。
2. ヘッダを読む。幅と高さだけを得る。`ImageDecoder` では `OnHeaderDecodedListener` の中で次の段階を決める。
3. 計画を立てる。下記の規則で、全体を 1 枚の画像にするか、タイルに分けるかと、縮小率を決める。
4. デコードする。
5. 後処理をする。余白の検出、表示サイズへの縮小、画像補正を行う。
6. `PageResult.Ready` を返す。

上限と計画の規則は次のとおり。

| 規則 | 内容 |
|---|---|
| 展開サイズの上限 | エントリの展開後の大きさが 256 MB に達したら、宣言サイズにかかわらず展開を止めて `Unsupported(TooLarge)` にする。宣言サイズは信用せず、実際に書き出した量で数える (要検証。上限の値)。ローカルヘッダを順に読む方式で、サイズをデータディスクリプタに持つ Deflate のエントリを飛ばすときは、libarchive が中で展開して捨てるので、この上限は掛からない。メモリは増えず、取り消しは読み込みのコールバックで効くが、展開の時間だけ掛かる。M3 の fuzz で時間を測り、問題なら上限を掛ける (要検証) |
| 寸法の妥当性 | 幅か高さが 0 以下か 1,048,576 を超える場合、または画素数が 2^28 を超える場合は `Unsupported(TooLarge)` にする。縦長画像の高さが 65,535 を超えても、画素数が上限内なら読む (要検証。各デコーダの寸法の上限) |
| 必要メモリの事前計算 | 出力の画素数 × 4 バイトを `Long` で計算し、割り当ての前に予算（5.3 節）と比べる |
| 縮小率 | 出力は表示に必要な大きさ以上、その 2 倍未満にする。JPEG は DCT 段階の縮小を使う。2 の累乗の縮小率をデコーダに渡し、残りは 5.3 節の方法で縮める。デコーダの縮小が面積平均にならない形式（PNG）は縮小率を 1 にする |
| 1 枚の上限 | 出力が 1 枚の描画上限（GPU の最大テクスチャサイズ、かつハードウェア描画で許される 1 枚の大きさ）を超える場合はタイルにする。タイルは M3 で作る。M1 では長辺 4,096 ピクセルに収まるまで縮小する (要検証。端末の最大テクスチャサイズ) |
| 縦長画像 | 縦横比が 1:3 より細長い画像は、表示倍率にかかわらずタイルにする |
| タイル | 1 枚 1024 × 1024 ピクセルを既定とする (要検証)。表示範囲と、その周囲 1 画面分だけを持つ |
| 予算不足 | 1 枚が予算の半分を超えるときは、失敗にせず縮小率を上げて読む。デコーダの縮小が間引きになる範囲や、出力が表示に必要な大きさを下回る範囲まで上げてもよい |
| 時間切れ | 1 回のデコードが 10 秒を超えたら `Failed(Timeout, retryable = true)` を返す。そのときまだ並列数の枠を待っているデコードは取り消し、始めない。デコード中のスレッドは止められないので、デコードの並列数の枠を持ったまま終わるまで動かし、結果を捨てる。ヘッダを読む前なら、ヘッダの段階の取り消しの確認で止まる |

タイルの読み込みは `BitmapRegionDecoder` を使う。対応する形式は JPEG、PNG、WebP、HEIF である (要検証。API 28〜30 での PNG とプログレッシブ JPEG の速度)。領域デコードできない形式は、上限内に縮小して全体を読み、メモリ上でタイルに切り分ける。

### 3.8 暗号化された入力

| 対象 | v1 の扱い |
|---|---|
| ZIP の暗号化エントリ（従来方式、AES） | `Unsupported(Encrypted)`。ページに「このページは暗号化されています」と出す。パスワード入力は Q4 で決める |
| RAR、7z の暗号化エントリ | `Unsupported(Encrypted)` |
| ヘッダまで暗号化された RAR 5、7z | 本を開いた時点で「暗号化された書庫には対応していません」と出し、リーダーは開かない |
| パスワード付き PDF | 本を開いた時点で同様に出す。Q4 |

### 3.9 PDF

- `android.graphics.pdf.PdfRenderer` で描く。
- `PdfRenderer` はシーク可能な `ParcelFileDescriptor` を必要とする。SAF ではそのまま渡す。SMB では `StorageManager.openProxyFileDescriptor` で `ByteSource` を包んで渡す (要検証。先読みの量と速度)。
- ページの大きさは描かずに得られるので、開いた時点で全ページの形が分かる。
- 各ページは表示サイズで白い背景に描く。拡大中は変換行列を使い、見えている範囲だけをタイルに描く。
- `PdfRenderer` は同時に 1 ページしか開けず、スレッドセーフでない。文書ごとに 1 つのセッションで直列に扱う。

### 3.10 画像フォルダ

- フォルダ直下の画像ファイルを 1 冊の本とする。サブフォルダは別の本として扱い、中身を混ぜない。
- 並び順と除外の規則は 3.5 節と同じである。

### 3.11 テキストファイル

- 対象はテキストと判定したファイルと、書庫内のテキストのエントリである。
- 文字コードは次の順で決める。BOM があれば UTF-8 か UTF-16 にする。先頭 64 KB が正しい UTF-8 なら UTF-8 にする。正しい CP932 なら CP932 にする。それ以外は `CharsetDetector` の結果にし、確からしさが低ければ設定に従う。候補には EUC-JP を含める。
- 改行は LF に統一する。

## 4. 画面仕様

### 4.1 画面の構成

| 画面 | 役割 | 実装 |
|---|---|---|
| ホーム | 本棚、履歴、しおりの 3 タブ | Compose、Material 3 |
| ファイル一覧 | 場所の中のフォルダと本を見る | 同上 |
| 場所の追加と編集 | SAF のフォルダ登録、SMB サーバーの登録 | 同上 |
| 書庫内一覧 | 1 冊の中のページとテキストを見る | 同上 |
| リーダー | 画像の本を読む | 描画面は Q1 で決める。周りの UI は Compose |
| テキストリーダー | テキストを縦書きで読む | 独自の組版エンジンと描画面 |
| 設定 | 4.10 節の設定 | Compose、Material 3 |
| ライセンス | 依存ライブラリのライセンス全文 | 同上 |

画面遷移は Navigation Compose で行う。戻る操作は predictive back に対応する。

### 4.2 ホームの本棚タブ

上から次の順に並べる。

1. 続きを読む。読みかけの本を最近開いた順に最大 10 冊、表紙と進み具合（%）付きで横に並べる。タップで保存位置から開く。
2. ピン留めしたフォルダ。どの場所のフォルダでもピン留めできる。
3. 場所の一覧。SAF のフォルダと SMB サーバー。末尾に **場所を追加** を置く。

場所を長押しすると、名前の変更、編集（SMB のみ）、削除を選べる。SAF の場所を削除すると、永続許可も解放する。

### 4.3 ファイル一覧

| 要素 | 仕様 |
|---|---|
| 上部バー | 現在のパス（タップで上位フォルダを選ぶ）、並べ替え、表示形式の切り替え、絞り込み |
| 項目の種類 | フォルダ、本（書庫、PDF、画像フォルダ）、テキスト、画像ファイル |
| 表示形式 | グリッド、サムネイル付きリスト、リスト。切り替えは設定に保存する |
| 形式の表示 | サムネイルの隅に `ZIP`、`RAR`、`7Z`、`PDF`、`TXT` の小さなラベルを出す |
| 読書状態 | 未読は点、読みかけは表紙の下端の進み具合バーと %、既読はチェックと薄い表紙。名前の色も状態で変える（下表）。色だけで区別しない |
| 補足情報 | リスト表示で、名前の下に `yyyy/MM/dd HH:mm` の更新日時と大きさ（例 `12.3 MB`）を出す。フォルダは日時だけ。幅が足りなければ 2 行にし、日付を短くする。開いたことのある本はページ数も出す |
| 絞り込み | 入力した文字列を名前に含む項目だけを出す。対象は今のフォルダの直下の項目だけで、サブフォルダの中や書庫の中は探さない。一覧はすでに読み込んだ項目から作り直すので、ストレージへの問い合わせは増えない。入力のたびに結果を更新する。NFKC で正規化し、大文字と小文字を区別しない。フォルダにも同じ条件を当てる。別のフォルダへ移ると絞り込みを解除する |
| 戻ったとき | リーダーから戻ると、開いていた本が見える位置まで一覧をスクロールする。上位フォルダへ戻ったときも、出てきたフォルダが見える位置に戻す |
| スクロール | 慣性スクロールはプラットフォームの標準に従う。右端に幅 48 dp の高速スクロールのつまみを出し、ドラッグで一覧全体を移動できる |
| 読み込み | 項目は取得した順に表示を始める。SAF では `DocumentsContract` の子文書を 1 回のクエリで名前、MIME 型、大きさ、更新日時ごと取る。読み込みが 300 ms を超えたら進行表示と取り消しを出す |
| 方向キー | 一覧の項目をフォーカスで移動し、Enter で開く |

名前の色はテーマのトークンで決める。ダークテーマの既定値は次のとおりで、ライトテーマでは同じ色相のより暗い色を使う。

| 状態 | トークン | ダークテーマの既定値 |
|---|---|---|
| 未読の本 | `stateUnread` | 白 `#FFFFFF` |
| 読みかけの本 | `stateReading` | シアン `#00FFFF` |
| 既読の本 | `stateRead` | 灰色 `#808080` |
| フォルダ | `stateFolder` | 緑 `#00FF00` |
| 単独の画像ファイル | `stateImage` | 黄 `#FFFF00` |
| 補足情報 | `itemDetail` | 灰色 `#9F9F9F` |
| 押している項目の背景 | `itemPressed` | 青 `#0040C0` |

タップしたときの動作は次のとおり。

| 項目 | 動作 |
|---|---|
| フォルダ | 中へ移動する |
| 本 | リーダーで保存位置から開く |
| テキスト | テキストリーダーで開く |
| 画像ファイル | そのフォルダを 1 冊の本としてリーダーで開き、その画像から表示する |

長押しで出すシートの項目は次のとおり。状態に合わない項目は出さない。

- 開く、中身を見る（書庫内一覧）、最初から読む
- 既読にする、未読にする
- 表紙を選ぶ（書庫内一覧で選ぶ）
- このフォルダを本として読む（画像を含むフォルダのみ）
- ピン留め、ホーム画面にショートカットを作成
- 端末に保存（SMB のみ。保存先は SAF で選ぶ）
- 名前を変更、削除（設定で許可したときのみ）
- サムネイルを作り直す

- 名前の変更は拡張子を保ち、拡張子より前の部分だけを編集させる。
- 削除は確認してから行う。フォルダは中身ごと消すので、確認に中の項目数を出す。

次の本と前の本は、同じフォルダの項目を自然順（フォルダを先）に並べて決める。一覧の並べ替えには左右されない。巻の順を名前の数字で決めるためである。画像のリーダーでは書庫、PDF、画像を含むサブフォルダを対象にし、テキストリーダーではテキストファイルを対象にする。

#### 起動時の動作

- 設定「起動時に前回の本を開く」が「尋ねる」なら、起動時に前回の本の名前を出して開くかどうかを尋ねる。「すぐ開く」なら、そのまま保存位置から開く。
- 起動の処理が 3 回続けて完了しなかったら、最後に見ていたフォルダと表示形式を既定に戻してホームから始める。

### 4.4 サムネイル

- 表紙は自然順で先頭のページにする。ユーザーが表紙を選んだ本はそのページにする。
- 表紙が横長のときは、右綴じでは右半分、左綴じでは左半分を使う。見開きでスキャンした表紙の、表側を出すためである。
- フォルダのサムネイルは、中を名前の自然順に再帰的に探して最初に読めた画像から作る。ユーザーが選んだ画像があればそれを使う。
- 生成は 2 周で行う。1 周目はディスクキャッシュだけを見て、画面に見えている項目をすぐ埋める。2 周目でキャッシュのない項目を実ファイルから作る。どちらの周も見えている項目を先にし、見えなくなった項目の生成は取り消す。
- 生成中は表紙の位置に淡い四角と進行表示を出し、失敗したら形式のアイコンを出す。
- サムネイルの隅に種類の印（フォルダ、ZIP、RAR、7Z、PDF）を出す。テキストは固定のアイコンにする。
- 生成の並列数は、ローカルで 2、SMB で 1 とする。
- 生成に失敗した本は失敗を記録し、同じ版のファイルでは再試行しない。

表紙はユーザーが変えられる。

- 書庫内一覧かリーダーで、ページを表紙に選べる。
- 範囲を切り抜いて表紙にできる（M6）。切り抜き画面は、選んだページの上に枠を出す。枠の縦横比の初期値はサムネイルのセルの比である。枠の中をドラッグすると移動し、辺をドラッグすると大きさが変わる。確定すると枠の中を表紙として保存する。
- 子の画像やページを「フォルダの表紙にする」で、親フォルダのサムネイルに使える。

### 4.5 場所の追加と SMB サーバー

SAF のフォルダは `ACTION_OPEN_DOCUMENT_TREE` で選び、`takePersistableUriPermission` で永続許可を取る。

SMB サーバーの入力項目は次のとおり。

| 項目 | 内容 |
|---|---|
| 表示名 | 一覧に出す名前 |
| ホスト | ホスト名か IP アドレス。ポートは既定で 445 |
| 共有名 | v1 では入力が必要。共有の一覧取得は Q17 |
| フォルダ | 共有の中の起点。空なら共有の最上位 |
| ドメイン | 任意 |
| ユーザー名とパスワード | 両方空なら匿名で接続する |

- **接続を試す** で接続と認証を確かめ、結果を「接続できました」か、失敗の理由（名前解決、到達不能、認証、共有がない）で出す。
- 対応する方言は SMB 2.0.2 から 3.1.1 までとする。署名と暗号化はサーバーとの交渉に従う。
- パスワードの扱いは 7 章に従う。編集画面にはパスワードを表示せず、変更するときだけ入力させる。
- 本棚では、サーバーを表示名と `smb://ユーザー名@ホスト/共有名/` の形で出す。パスワードは出さない。
- サーバーの中はローカルと同じファイル一覧で見る。一覧の取得に 300 ms 以上かかったら進行表示と取り消しを出す。
- 登録できるサーバーの数に上限は設けない。

「端末に保存」の動作は次のとおり。

1. 保存先のフォルダを SAF で選ぶ。前回選んだフォルダを初期値にする。
2. `名前.part` という一時的な名前で書き、終わったら本来の名前に変える。
3. 同じ名前があれば、`名前 (1)` から `名前 (9)` の順に空いている名前を使う。すべて埋まっていれば失敗として知らせる。
4. フォルダは中身ごと再帰的に保存する。
5. 進み具合を、バイト数と % で通知に出す。取り消すと一時ファイルを消す。

### 4.6 履歴タブとしおりタブ

| タブ | 仕様 |
|---|---|
| 履歴 | 既定は新しい順。表紙、名前、場所、進み具合を出す。タップで保存位置から開く。左右のスワイプで 1 件消し、メニューで全件消す |
| しおり | 本ごとにまとめる。タップでその位置から開く。長押しで名前の変更と削除 |

- 並べ替えは、履歴ではパスの昇順、降順、古い順、新しい順から選ぶ。しおりではさらに名前の昇順と降順を選べる。選んだ並びは保存する。
- 長押しのメニューに「フォルダを開く」を置き、その本のあるフォルダをファイル一覧で開く。
- しおりのまとめ削除は、すべて、見つからない本のもの、指定したフォルダの下のもの、指定した場所（端末内か各サーバー）のもの、から選ぶ。
- 本を閉じたときに履歴へ加える。同じ本はいちばん新しい位置へ移す。

### 4.7 書庫内一覧

- 上部バーに本の名前を出す。
- ページを番号順のサムネイルのグリッドで出す。リスト表示に切り替えると、エントリ名、更新日時、大きさを出す。テキストのエントリは先頭にリストで出す。
- 保存位置より前のページは既読の色で薄く出す。テキストのエントリはそれぞれ読書状態を持ち、長押しで未読と既読を切り替えられる。
- 読めないページはサムネイルの位置にエラーの印を出す。
- タップでそのページからリーダーで開く。テキストのエントリはテキストリーダーで開く。
- 長押しで「ここまで読んだことにする」と「このページを表紙にする」を選べる。
- メニューで文字コードを選び直せる（3.4 節）。

### 4.8 リーダー

#### 画面の領域

```
+----------------------------------+
| コマンドバー（高さは設定に従う）    |
+----------------------------------+
|                                  |
|            めくり領域              |
|                                  |
+----------------------------------+
| ページバー（高さは設定に従う）      |
+----------------------------------+
```

- コマンドバーとページバーの高さは同じで、設定「バーの高さ」（既定 60 dp）に従う。
- システムバーを隠しているとき、画面の上端と下端から 6 dp 以内で始まるタッチは無視する。システムのジェスチャー領域から始まる操作は、システムに渡す (要検証。ノッチのある端末で確かめる)。
- リーダーには 1 本指のダブルタップ操作を置かない。ダブルタップを待つと、すべてのタップのめくりが待ち時間の分だけ遅れるためである。

#### タップ領域

めくり領域を、設定「タップ領域の配置」と「タップの帯の幅」で分ける。帯の幅は、配置の向き（左右なら幅、上下なら高さ）に対する % である。

| 配置 | 戻る | 進む | 何もしない |
|---|---|---|---|
| 片側の帯（既定） | 右端の帯 | 残りの全部 | なし |
| 両側の帯 | 右端の帯 | 左端の帯 | 中央 |
| 上下 | 上の帯 | 残りの全部 | なし |
| 上下の帯 | 上の帯 | 下の帯 | 中央 |

- 既定では、右端 10% をタップすると戻り、それ以外をタップすると進む。右手で持ったとき、親指の付け根の側が戻るで、届く範囲のほとんどが進むになる。
- 帯の位置は綴じ方向では変わらない。左手で持つ人は「左右を反転」で帯を左に移す。
- 両側の帯と上下の帯では、各帯の幅の上限を 45% にする。
- 設定「左右を反転」で、タップの帯の左右とスワイプの向きをまとめて入れ替える。
- 「何もしない」領域のタップは、拡大中に画像を動かしたあとの誤ったタップでめくらないための領域である。
- タップは指を離した時点で確定する。移動量がタッチスロップ以内で、長押しの時間に達していないものをタップとする。
- 拡大中で、設定「タップで停止点を進める」が有効なら、タップは次の停止点へ移動する。最後の停止点の次で次のビューへ進む。

#### コマンドバー

コマンドバーは、押して滑らせて離す 1 動作でコマンドを実行する。

1. コマンドバーに指を置くと、すぐにコマンドパネルをバーの下に開く。システムバーを隠しているときは、400 ms 押し続けてから開く。画面の端から引き出すシステムの操作と取り違えないためである。パネルの最上段の左端には **閉じる**、右端には **メニュー** を常に置く。
2. 指を滑らせると、指の下の項目を強調し、強調が変わるたびに軽い触覚フィードバックを返す。
3. 項目の上で指を離すと、そのコマンドを実行してパネルを閉じる。項目のない位置で離すと何もせずに閉じる。
4. 指を動かさずに離した（タップした）ときは、パネルを開いたままにする。続けて項目をタップすれば実行し、外をタップすれば閉じる。

パネルの項目は設定「コマンドバーの項目」で選び、並べ替える。縦画面では 4 列 × 2 段、横画面では 8 列 × 1 段で並べる。この格子は **閉じる** と **メニュー** の段の下に置き、左上から段ごとに詰める。**閉じる** はリーダーを閉じる。触覚フィードバックは、指の下に新しい項目が来たときに返す。開いたパネルの外を押すとパネルを閉じ、パネルの中の項目のない位置をタップしてもパネルは開いたままにする。パネルの背景は半透明の紺（`#80000070`）とし、右下に時刻と電池の残量を出す。選べるコマンドは次のとおり。

| コマンド | 動作 |
|---|---|
| 組み方 | ページの組み方を順に切り替える |
| 組ずらし | 組を 1 枚後ろへずらす |
| 拡大モード | 拡大モードを順に切り替える |
| 余白トリミング | 強さを順に切り替える |
| 綴じ方向 | 右綴じと左綴じを切り替える |
| 回転 | 画像を 90 度ずつ回す |
| 画面の向き | 縦固定、横固定、端末に従う、を切り替える |
| しおりを追加 | 現在の位置にしおりを付ける |
| しおり一覧 | この本のしおりを出す |
| 自動再生 | 自動再生を始める |
| 並びを逆に | ページの並びを逆にする |
| 画像補正 | 明るさ、シャープ、グレースケール、白黒反転のパネルを出す |
| 操作の反転 | 「左右を反転」を一時的に切り替える。保存しない |
| 停止点の順序 | 行ごとと列ごとを切り替える |
| 綴じ目の表示 | なし、すき間、影を順に切り替える。保存しない |
| コマンドバーの編集 | コマンドバーの項目を選ぶ画面を開く |
| 息で操作 | 息での操作を切り替える（M6） |
| 本ごとの設定 | 本ごとの設定のシートを出す |
| 表紙にする | 現在のページをこの本の表紙にする |
| ページを共有 | 現在のページの画像を共有する |
| 設定 | 設定画面を開く |

既定の項目は、画面の向き、余白トリミング、組み方、拡大モードの 4 つとする。

#### ページバー

ページバーは、指を置いて横に滑らせてページを選ぶ。

| 段階 | 仕様 |
|---|---|
| 押す | 押した位置を基準点にする。画面の上部に `12 / 200`、本のパス、エントリ名の帯を出し、バーの上に移動先のサムネイルを出す |
| 滑らせる | 基準点からの距離に応じてページ数を変える（下記）。右綴じでは左へ滑らせると先のページへ進む |
| 端に達する | バーの端から 24 dp 以内に入ると、先頭ページか最終ページを選ぶ |
| 離す（バーの中） | 選んだページへ移動する。アンカーをそのページにする |
| 離す（バーの外） | 指をバーの高さ以上、上へ外してから離すと取り消す。プレビューは外れた時点で灰色にする |
| タップ | ページパネルを開く |
| 400 ms の長押し | 指を動かさずに 400 ms 押し続けても、ページパネルを開く |

距離とページ数の対応は、単位 u = 5 dp を使った階段で決める。最初は鈍く、そのあと一定の速さになる。

| 基準点からの距離 | 動くページ数 |
|---|---|
| 0〜10 dp 未満（2u） | 0 |
| 10 dp（2u） | 1 |
| 30 dp（2u + 4u） | 2 |
| 45 dp（2u + 4u + 3u） | 3 |
| それ以降 | 5 dp（1u）ごとに 1 ページ |

- 最初の 1 ページは軽く動き、2 ページ目までは指を大きく動かさないと進まない。押したときの指のぶれで 2 ページ以上動かないためである。
- 3 ページ目からは 5 dp ごとに 1 ページずつ動く。遠くのページへは、バーの端まで滑らせて先頭か最終ページを選ぶか、ページパネルを使う。
- 単位 u の 5 dp は既定値であり、試作で調整する (要検証)。
- 滑らせる向きは綴じ方向だけで決め、「左右を反転」では変えない。
- 端の 24 dp 以内で押したときは、指が一度その範囲を出てから戻ったときに端のページを選ぶ。押したときの指の位置で先頭や最終ページに飛ばないためである。

ページパネルは次のものを持つ。外側をタップするか戻る操作で閉じる。

- 横にスクロールするサムネイルの帯。並ぶ向きは綴じ方向に合わせ、右綴じでは右から左へ並べる。タップで移動する。帯のサムネイルを描いている間は、先読みを止める。
- スライダー。並ぶ向きはサムネイルの帯と同じにする。ドラッグ中は 100 ms ごとに移動先のページを本体に表示し、離すと確定する。
- ページ番号の入力欄と、−100、−10、−1、+1、+10、+100 のボタン。押すたびに本体の表示を移動先に変える。
- **取り消す** で、パネルを開いたときのページに戻す。
- ボタン。先頭、末尾、組ずらし（前、後）、前の本と次の本（それぞれ続きから、先頭から、末尾から）、しおり一覧、閉じる。

#### めくり効果

| 効果 | タップとキーでめくったとき | 指で引いてめくったとき |
|---|---|---|
| なし | すぐに切り替える | 引いた量の目安を端に出し、離すとすぐに切り替える |
| スライド | 今のビューと次のビューが並んで動く | 指に合わせて 2 つのビューが動く |
| 重ねる | 次のビューが今のビューの上に滑り込む | 指に合わせて次のビューが滑り込む |
| フェード | 次のビューが現れる | スライドと同じ |

- 既定の効果は「重ねる」とする。
- 効果の動く向きは、進むか戻るかと綴じ方向で決める。右綴じで進むときは、次のビューが左から入る。
- 効果の長さは設定「めくりの長さ」（既定 150 ms）に従う。
- 「スライド」と「重ねる」では、指で引いている間、隣のビューを引いた量だけ見せる。
- 次のビューは効果の最初のフレームから描く。効果がめくりの開始を遅らせてはならない。
- 指で引いてめくったときは、離した位置から残りを、効果の長さに残りの割合を掛けた時間で動かす。フェードも離した後はスライドとして動かす。
- 効果の途中で次の入力が来たら、今の効果を即座に終え、新しい入力を処理する。
- ページを指定して移動したときは効果を付けない。

#### 端引きでめくる

- ビューがスワイプの向きに画面からはみ出していなければ、横のドラッグはそのまま端引きになる。
- 拡大中は、ドラッグは画像をスクロールする。指を置いた時点で画像がその向きの端にあった場合だけ、端引きになる。スクロールの勢いで次のページに入ってしまうことを防ぐためである。
- ドラッグの開始は、指の移動量がタッチスロップを超えた時点とする。
- 引ける量の上限は 150 dp とする。上限に近づくほど抵抗を付け、指の移動より少なく動かす。引いた量は、指の移動 d が 75 dp までは d とし、その先は 75 + 75 × tanh((d − 75) / 75) dp とする。135 dp に届くのは指が約 158 dp 動いたときである (要検証)。
- 離したときに引いた量が上限の 90%（135 dp）以上なら、めくる。引いた量が 24 dp 以上で、めくる向きの速度が 1000 dp/s 以上のときもめくる。どちらでもなければ、約 120 ms で元の位置に戻す (要検証)。
- 右綴じでは右へ引くと次のビューへ進む。左綴じでは左へ引くと進む。「左右を反転」で入れ替わる。
- 指を離したあとの慣性スクロールで端に着いても、めくらない。
- 設定「スワイプでめくる」が無効なら、ドラッグはスクロールだけを行う。

#### 見開き

- 組み方は 2.5 節の規則に従う。
- 2 ページの組は、2 枚を同じ高さにそろえてから、組全体を拡大モードで画面に合わせる。
- 綴じ目の表示は、なし、すき間、影から選ぶ。既定はすき間である。
  - すき間は、2 枚の間を 2 px 空け、背景色で塗る。
  - 影は、各ページの綴じ側にページ幅の 5% の暗いグラデーションを重ねる (要検証。影の濃さ)。
- 組の 2 枚の高さが違うときは、低い方を拡大して高い方にそろえる。
- 本ごとの設定で、綴じ方向、組み方、表紙の単独表示を本ごとに持つ。

#### 余白トリミング

余白の検出は次の手順で行う。

1. 長辺 512 ピクセルに縮小したグレースケールの複製で解析する。
2. 白い余白と黒い余白の両方を扱う。各辺の外側 2% の帯から背景の明るさを求める。帯の明るさのばらつきが大きい辺は、絵が紙の端まである辺とみなし、切らない。
3. 端から内側へ 1 行（1 列）ずつ調べる。背景との差が 32 段階を超える画素の割合が、強さごとのしきい値未満の行を余白とする。調べるのは、辺の長さのうち強さごとの調べる範囲までとする。
4. 余白でない行が 2 行続いたところを内容の始まりとする。孤立したゴミや汚れで止まらないためである。
5. 見つけた余白のうち、強さごとの切る割合だけを切る。残りは内容の周りの余白として残す。

| 強さ | 画素の割合のしきい値 | 調べる範囲（辺の長さに対して） | 見つけた余白のうち切る割合 |
|---|---|---|---|
| 弱 | 0.5% | 25% | 60% |
| 中 | 0.6% | 30% | 80% |
| 強 | 0.7% | 45% | 90% |
| 最強 | 0.8% | 100% | 100% |

切りすぎを防ぐ規則は次のとおり。

- 切った後の幅か高さが 20 px 以下になるなら、そのページは切らない。
- 切った後の幅か高さが元の 50% 未満になるなら、そのページは切らない。
- 切った後の縦横比が、切る前の縦横比から 30% 以上変わるなら、そのページは切らない (要検証)。
- 2 ページの組では、上下の切り幅を 2 枚の小さい方にそろえる。2 枚の高さがずれないためである。
- 横長ページでは、左右の切り幅を小さい方にそろえる。綴じ目が中央からずれないためである。
- ページの形（横長かどうか）は切る前の寸法で決める。トリミングでビューの組み方は変わらない。
- 解析の結果は、ページと強さの組ごとにメモリに保持する。

#### 拡大モード

| モード | 動作 |
|---|---|
| 画面に収める | ビュー全体が画面に入る最大の倍率 |
| 幅に合わせる | ビューの幅を画面の幅に合わせる。縦にはみ出した分は停止点で読む |
| 高さに合わせる | ビューの高さを画面の高さに合わせる。横にはみ出した分は停止点で読む |
| 原寸 | 画像の 1 ピクセルを画面の 1 ピクセルで表示する |
| 画面いっぱい | 縦横比を無視して画面全体に広げる |

- 拡大モードはビュー単位で効く。縦画面で横長ページを単独表示して「高さに合わせる」にすると、横に 2 画面分の幅になり、停止点で右から読める。
- 設定「拡大は原寸まで」が有効なら、どのモードでも倍率の上限を原寸にする。

#### ピンチと拡大率

- 2 本の指の間隔が 20 dp 以上変わった時点でピンチを始める。
- 範囲は「画面に収める」倍率の 0.5 倍から 8 倍までとする。指の動きが大きいほど倍率の変化を速くする。倍率は、ピンチを始めたときの指の間隔に対する今の間隔の比の 1.5 乗で変える (要検証)。「拡大は原寸まで」が有効なら、ピンチの上限も原寸までとする。
- ピンチ中は画面の中央に倍率を `150%` の形で出す。100% は拡大モードの倍率を表す。
- 指を離すと、その倍率に合った解像度でタイルを読み直す。読み直す間は今の画像を引き伸ばして出す。
- ピンチ中に、2 本目の指で 1 秒以内に 2 回タップすると、拡大モードの倍率に戻す。2 本指の操作なので、1 本指のタップを待たせない。
- 拡大率はめくっても保つ。拡大モードを変えたとき、または「画面に収める」倍率を下回って離したときは、拡大モードの倍率に戻す。

画像補正は、縮小、回転、シャープ、グレースケール、白黒反転、明るさの順に掛ける。補正は準備済みのビューを作るときに済ませ、描画のたびには掛けない。

#### 回転と画面の向き

- 本ごとの設定で、画像を 90 度単位で回せる。横向きにスキャンされた本のためである。回した後の寸法でページの形を決める。
- 設定「画面の向き」で、リーダーの向きを端末に従う、縦、横から選ぶ。コマンドでも切り替えられる。
- 向きが変わったら、現在のビューの先頭ページをアンカーにして組み直す。

#### 停止点

- 画面より大きいビューは、2.6 節の停止点で読み進める。既定の最大移動量は画面の 35% である。
- 停止点の間は、毎秒約 1750 dp（4 ms で 7 dp）の一定の速さで動かす。移動中の入力は「めくり効果」と同じ規則で扱う。
- 停止点で進むのは、音量キー、タップ（設定が有効なとき）、自動再生、息での操作である。
- 拡大中に指で動かしたあとに停止点で進むと、今の表示位置より先にある最も近い停止点へ進む。「先」は停止点の順序で決める。行ごとなら、より下の段か、同じ段で読む向きに先の点である。`Two` のビューでは、表示位置に横で最も近いページの残りを先に読む。
- `Two` のビューを 1 ページずつ読むのは、ビューが画面より横に広いときだけとする。横に収まるビューは組全体を 1 つの内容として停止点を求める。どちらでも、停止点は画面がビューの外に出ない位置に丸める。

#### ルーペ

1. めくり領域で、設定「ルーペを出す長押しの長さ」（既定 0.8 秒）だけ指を動かさずに押すと、触覚フィードバックとともにルーペを出す。
2. 画面を縦横に 2 分した 4 つの区画のうち、指のある区画と対角の区画にルーペを出す。指を動かすと、指の下の部分を拡大して見せる。
3. 指がルーペのある区画に入ると、ルーペは指から最も遠い区画へ 150 ms で移る。移ったばかりの区画へすぐ戻らないように、指が区画の境界から 24 dp 以上離れるまで次の移動をしない。
4. 指を離すとルーペを消す。ルーペを出している間はめくらない。

- 倍率は、表示の 1.5 倍、2 倍、2.5 倍、3 倍と、元画像の 1 倍、2 倍、3 倍から選ぶ。既定は表示の 2 倍である。元画像の倍率では、タイルから元の解像度の画素を読む。
- ルーペは長方形で、幅と高さはそれぞれ画面の幅と高さの、小 7/16、中 8/16、大 9/16 とする。区画の外側の角に寄せて置く。大では画面の中央線を少し越える。

#### 重ねて表示する情報

| 情報 | 仕様 |
|---|---|
| ページ番号 | `12 / 200`。2 ページの組では `12-13 / 200`。位置は 6 か所から選ぶ。出すときの既定の位置は下中央 |
| 時刻と電池 | `21:05 [80%]` の形。時刻は端末の 12 時間と 24 時間の設定に従う。充電中は `[80%]` の後に、USB なら `[USB]`、電源アダプタなら `[AC]` を付ける。出すときの既定の位置は右下 |
| 読み込み中 | 次のビューの準備ができていなければ、めくりは止めずに先へ進む。サムネイルがあればそれを引き伸ばして出し、なければ背景色にする。300 ms たっても準備できなければ、中央に進行表示を出す。読み込み中もタッチ操作は受け付ける |
| 取得の状況 | SMB から読んでいるときは、進行表示の下に取得元（メモリ、キャッシュ、端末、サーバー）と `45% 820 KB/s` の形の進み具合を出す |
| 接続状態 | SMB の接続が切れて再接続している間は、上部に「再接続しています」と出す |
| 息での操作 | 右上にマイクの印、判定の状態、入力の大きさを出す（M6） |

文字の大きさは、小 12 sp、中 16 sp、大 20 sp とする。文字は白に黒の縁取りを付けて、明るい画像の上でも暗い画像の上でも読めるようにする。

#### ページのエラー表示

- `Failed` と `Unsupported` のページは、そのページの位置にエラーカードを出す。2 ページの組の片方だけが失敗したときは、もう片方を普通に表示する。
- カードには、理由を 1 行、エントリ名、操作を出す。理由の文言は次の表のとおり。

| 結果 | 文言の例 | 操作 |
|---|---|---|
| `Failed(Corrupt)`、`Failed(Truncated)` | このページのデータは壊れています | 詳細 |
| `Failed(ReadError)`、`Failed(ConnectionLost)` | このページを読み込めませんでした | 再試行、詳細 |
| `Failed(Timeout)` | 読み込みに時間がかかりすぎました | 再試行 |
| `Unsupported(Encrypted)` | このページは暗号化されています | 詳細 |
| `Unsupported(Compression)` | 対応していない圧縮方式です（方式名） | 詳細 |
| `Unsupported(ImageFeature)` | 対応していない画像です（内容） | 詳細 |
| `Unsupported(TooLarge)` | 画像が大きすぎます（幅 × 高さ。幅と高さが 0 のときは出さない） | 詳細 |
| `Unsupported(NotAnImage)` | 画像ではありません | 詳細 |

- **再試行** は、表の行にかかわらず `retryable` が真のときに出し、偽のときは出さない。表の操作の列は、各理由でふつう起きる `retryable` の値のときの例である。
- エラーのページも普通にめくって通り過ぎられる。
- すべてのページが失敗した本は、リーダーを開いたまま本全体のエラーを出し、ファイル一覧へ戻る操作を出す。
- **詳細** は、形式、エントリ名、判定した種類、例外の種類を出し、テキストとしてコピーできる。

#### キー操作

| キー | 動作 |
|---|---|
| 左右の方向キー | めくる。右綴じでは左キーで進む。「左右を反転」に従う |
| 上下の方向キー | 組ずらし。上で戻る向き、下で進む向き。組でないビューでは何もしない |
| Page Down、Space、Enter | 進む |
| Page Up、Shift+Space | 戻る |
| Move Home、Move End | 先頭と末尾へ |
| 音量キー | 設定「音量キー」に従い、停止点を進めてから次のビューへ。停止点の順序は設定「停止点の順序」に従う。押下と解放の両方を消費し、音量を変えず、操作音も鳴らさない |
| ゲームパッドの L1、R1 | 戻る、進む |
| Menu | メニューを開く |
| 戻る、Del | 操作ガイドを出していれば閉じる。パネルを開いていれば閉じる。本を開いている途中なら開くのを取り消す。どれでもなければ、位置を保存してリーダーを閉じる |

- Bluetooth のページめくりリモコンは、方向キー、Page Up と Page Down、音量キー、Enter のいずれかを送るものが多い。上の割り当てでどれにも対応する。
- どのキーでも自動再生は止まる。
- キーの長押しには別の動作を割り当てない。押し続けたときのキーの繰り返しは、1 回ずつの押下として扱う。

#### 自動再生

- 設定「自動再生の間隔」（既定 1.5 秒）ごとに、次の停止点へ、停止点がなければ次のビューへ進む。
- 再生中は画面を消さない。
- タッチ、キー、メニューで止まる。止めるためのタッチはめくりに使わない。
- 本の末尾で止まり、次の本へは進まない。

#### 本の端での動作

設定「本の端での動作」に従う。

| 値 | 末尾で進む | 先頭で戻る |
|---|---|---|
| 確認する（既定） | シートを出す。次の本（続きから、先頭から）、最初から読む、閉じる | シートを出す。前の本（続きから、末尾から）、閉じる |
| 次の本へ | 次の本を先頭から開く | 前の本の最後のビューを開く |
| 閉じる | リーダーを閉じる | 何もしない |
| 止まる | 端で軽く跳ね返す動きを出す | 同左 |

- 次の本がないときは、「このフォルダの最後の本です」と出す。
- 自動再生中に末尾に着いたときは、設定にかかわらず止まるだけにする。
- シートには「位置を戻して閉じる」も置く。選ぶと、この本を開いたときの読書位置と読書状態に戻して閉じる。拾い読みで位置を動かしたくないときのためである。

#### メニュー

メニューは画面下からのシートで、幅は画面の短辺の 95%（上限 400 dp）とする。外側のタップ、戻る操作、Menu キーで閉じる。項目は次の 3 群に分ける。

1. この本の操作。しおりを追加、しおり一覧、本ごとの設定、表紙にする、範囲を選んで表紙にする（M6）、ページを共有、位置を戻して閉じる。
2. 読み方の操作。自動再生、息で操作（M6）、画面の向き、操作の反転、操作ガイド。
3. 設定とアプリの情報。設定、コマンドバーの編集、このアプリについて。

- しおり一覧は、この本のしおりを `名前（p. 12）` の形で出す。タップでそこへ移動する。
- しおりの既定の名前は 2.8 節に従う。追加するときに名前を変えられる。

本ごとの設定のシートは、綴じ方向、組み方、表紙の単独表示、拡大モード、余白トリミング、回転、並びを逆に、文字コード、画像補正（明るさ、シャープ、グレースケール、白黒反転）、画面の明るさを持つ。

- 変えた値はその場で本体の表示に反映する。
- 下部に **元に戻す**（シートを開いた時点の値に戻す）、**全体の設定に戻す**、**既定にする**（今の値を全体の設定にする）を置く。

操作ガイドは、半透明の層の上にタップ領域、コマンドバー、ページバーの範囲と名前を描く。どこかをタップすると閉じる。初めてリーダーを開いたときに 1 回だけ自動で出す。

#### ページの共有

- 現在のページの元のデータを、判定した MIME 型で `ACTION_SEND` に渡す。2 ページの組ではどちらのページかを選ばせる。
- 共有用の一時ファイルはキャッシュディレクトリの `share/` に置き、`FileProvider` で渡す。リーダーを閉じたときとアプリの起動時に消す。

### 4.9 テキストリーダー

#### 組版

- 縦書きで、行は右から左へ進む。v1 は縦書きだけとする（Q11）。
- 字形の選択は OpenType の `vert` と `vrt2` 機能に任せ、句読点、括弧、長音記号、ダッシュ、三点リーダーを縦書き用の字形にする (要検証。システムフォントでの対応)。
- 欧文と数字は設定「縦書き中の欧文」に従う。

| 値 | 動作 |
|---|---|
| 短い英数字を縦中横（既定） | 半角英数字と記号の 2 文字までの並びは縦中横にし、それより長い並びは時計回りに 90 度回して置く |
| 横倒し | 半角英数字の並びをすべて 90 度回して置く |
| 1 字ずつ正立 | 半角英数字を 1 字ずつ立てて置く。ただし 2 桁の数字と `!!`、`!?`、`?!`、`??` は縦中横にする |

- `⑴` から `⒇` の括弧付き数字は、どのモードでも 1 字分に収めて立てて置く。
- 括弧、長音記号、波ダッシュは縦書き用に回すか鏡映した字形にする。小書きの仮名は字面の右上に寄せる。
- `――` と `……` は 2 字分を切れ目のない 1 本の線と点の並びで描く。
- 禁則処理は追い出しだけで行い、ぶら下げはしない。行頭に来てはならない文字（閉じ括弧、句読点、小書きの仮名、長音記号など）が行頭に来るときは、前の行の最後の 1 文字と一緒に次の行へ送る。行末に来てはならない開き括弧は次の行へ送る。
- ルビは親文字の右側に、本文の 0.6 倍の大きさで置く。ルビが親文字より長いときは、隣の文字のルビのない側へはみ出させ、それでも足りなければ親文字の字間を広げる (要検証)。
- 隣どうしのルビが重なるとき、また傍点とルビが重なるときは、後の側を重ならない位置まで行方向にずらす。
- 行の途中で親文字とルビを分けない。
- 本文の 1 行目は表題とみなし、見出しの大きさで描く。
- 各ページの上部中央に表題を、下部中央に `12 / 300` の形でページ番号を出す。

#### 青空文庫記法の対応範囲

| 記法 | 扱い |
|---|---|
| ルビ `《》` と親文字の始まり `｜` | 対応する。`｜` がなければ、直前に続く同じ文字種（漢字など）を親文字にする |
| 改ページ、改丁、改見開き | すべて改ページとして扱う |
| ページの左右中央 | そのページの内容を行方向の中央に置く |
| 字下げ（1 行、ここから〜ここで終わり） | 対応する |
| 地付き、地から N 字上げ | 対応する |
| 見出し（大、中、小） | 太字で本文の 1.2 倍の大きさにし、目次に載せる |
| 傍点 | ゴマ、白ゴマ、丸、白丸、黒三角、白三角、二重丸、蛇の目の 8 種。右側（既定）と左側。直前の語への指定と、範囲の指定の両方 |
| 傍線 | 実線、二重線、鎖線、破線、波線。左右と範囲の指定は傍点と同じ |
| 太字 | 太字の書体で描く |
| 縦中横 `［＃「…」は縦中横］` | 対応する |
| 挿絵 `［＃…（ファイル名）入る］` | テキストからの相対パスで読む。書庫の中でも同じで、`../` も解釈する。注記の直後が改行なら独立した段落としてページの幅に収めて置き、文の途中なら本文 1 字分の大きさで行の中に置く |
| 外字 `※［＃…、第3水準1-85-6］` | 面区点番号を Unicode に変換する。変換表は Q13。丸数字、ローマ数字、濁点付きの仮名、合字の年号（㍻ など）を名前で指定する外字も変換する |
| くの字点 `／＼`、`／″＼` | 縦書き用のくの字点（〳〵、〴〵）に置き換える |
| 冒頭の記号説明 | 2 行目から 500 行目までの間で、`-` だけが 40 字以上続く行 2 本に挟まれた部分を表示しない |
| それ以外の注記 | 注記の部分を表示しない。本文は残す |

#### ページ分割

- 開くと先頭から約 10,000 文字ずつ、バックグラウンドで組んでいく。最初の区切りを組み終えた時点で 1 ページ目を出す。
- 全部を組み終えるまでは、総ページ数を「約」付きで出す。
- 位置は文字の通し番号で持つ。文字の大きさ、書体、画面の向きを変えたら、現在の文字を含むページから組み直す。
- 組み方は、1 ページ、見開き、連続、自動（画面が横長なら見開き、縦長なら 1 ページ）から選ぶ。連続は、ページを右から左へ横一列に並べ、指でなめらかにスクロールさせる。見開きでは綴じ目の表示の設定に従う。
- 描いたページは、現在のページの前後 2 ページを先に描いておき、合わせて最大 5 ページを持つ。

#### 操作

- タップ領域、コマンドバー、ページバー、端引き、キー操作、音量キーは画像のリーダーと同じ規則と設定に従う。テキストの左右はいつも右綴じとして扱う。
- めくり効果は画像のリーダーと同じ設定に従う。
- コマンドバーの項目は、目次、検索、しおりを追加、しおり一覧、文字の大きさ、組み方、画面の向き、設定から選ぶ。
- 目次は見出し記法から作る。見出し記法がない本では、次の条件をすべて満たす行を見出しとみなす。40 字未満である。前の行が空である。2 行前が `。` か `）` で終わらない。
- 検索は NFKC で正規化し、大文字と小文字を区別せずに本文を探す。ルビ、挿絵、傍点は対象にしない。結果を前後の文脈付きの一覧で出し、選ぶとそのページへ移動して該当箇所を色付きの矩形で強調する。強調の色はライトテーマで薄紫（`#EBC5E2`）とする。
- しおりの既定の名前は、全体に対する位置の % とする（2.8 節）。

#### 書体と色

- 書体は、システムの明朝体、システムのゴシック体、ユーザーが取り込んだ書体から選ぶ。
- 書体の取り込みは SAF で TTF、OTF、TTC を選び、アプリの内部領域に複製する。アプリは書体をダウンロードしない。
- 色は「紙の色」のプリセットで決める。文字色と背景色だけは、プリセットを上書きする色を選べる。

| 紙の色 | 背景 | 文字 |
|---|---|---|
| 白 | `#FFFFFF` | `#000000` |
| 生成り（既定） | `#FFFFC8` | `#000000` |
| セピア | `#F4ECD8` | `#5B4636` |
| 黒 | `#000000` | `#D0D0D0` |

- 本文の外側の余白とページの間は、画像のリーダーと同じ背景色で塗る。

### 4.11 その他

#### 設定の書き出しと読み込み

- 設定を JSON ファイルに書き出す。保存先は `ACTION_CREATE_DOCUMENT` で選ぶ。
- 書き出す内容は、全体の設定、コマンドバーの項目、本ごとの設定である。読書位置、しおり、履歴は、チェックを入れたときだけ含める。
- SMB サーバーは表示名、ホスト、ポート、共有名、フォルダだけを書き出す。ユーザー名、ドメイン、パスワードは書き出さない。
- ファイルには形式の版番号を入れる。読み込み時は、知らない項目を無視し、範囲外の値を範囲内に丸め、型の合わない値は既定値にする。
- 読み込む前に、変わる項目の数を出して確認する。

#### ショートカット

- フォルダと本について、`ShortcutManager.requestPinShortcut` でホーム画面のショートカットを作れる。
- ショートカットは場所の ID とパスを持ち、資格情報を持たない。対象が見つからなければ、その旨を出してホームを開く。

#### 他アプリから開く

`ACTION_VIEW` で次の MIME 型を受け付ける。受け取った後は中身で形式を決める。

- `application/zip`、`application/x-cbz`、`application/vnd.comicbook+zip`
- `application/x-rar-compressed`、`application/vnd.rar`、`application/x-cbr`、`application/vnd.comicbook-rar`
- `application/x-7z-compressed`、`application/x-tar`、`application/pdf`
- `text/plain`、`image/*`
- `application/octet-stream`（拡張子が対応形式のときだけ一覧に出す）

受け取った URI は、可能なら永続許可を取る。取れなければ、そのとき限りで開き、読書位置は Q10 で決めた方法で記録する。

#### 息での操作（M6）

- マイクの入力で、息を吹きかけてめくる。既定はオフで、オンにするときに `RECORD_AUDIO` の許可を求める。
- 入力は 8 kHz、モノラルで、100 ms ごとの区間の最大振幅を使う。
- オンにした直後に 2 秒間、周囲の音の大きさを測って基準 A にする。
- 判定は 2 つのしきい値で状態を持たせる。区間の値が「音あり」のしきい値以上なら音あり、「無音」のしきい値未満なら無音とし、その間なら直前の状態を保つ。しきい値は基準 A からの倍率と、下限の値で決める。

| 感度 | 音ありのしきい値 | 無音のしきい値 | 短い音の確定に要る無音の区間 | 長い音とみなす長さ |
|---|---|---|---|---|
| 低 | max(A × 6, 2000) | max(A × 3, 1000) | 4 区間（400 ms） | 12 区間（1.2 s）を超える |
| 中（既定） | max(A × 4, 1500) | max(A × 2, 800) | 3 区間（300 ms） | 8 区間（0.8 s）を超える |
| 高 | max(A × 3, 1000) | max(A × 1.5, 500) | 2 区間（200 ms） | 4 区間（0.4 s）を超える |

振幅は 16 ビットの値（最大 32767）で表す。倍率と下限は実機で調整する (要検証)。

- 短い音は、音ありのあとに無音が決まった区間数続いた時点で確定する。短い音が 1 回なら進み、確定の前に 2 回目が来れば戻る。
- 長い音は、続いている間、停止点の方向へ毎秒約 500 dp（4 ms で 2 dp）でなめらかにスクロールする。長い音の 1 回目は進む向き、次の長い音は戻る向きと交互に変える。
- 判定中は画面を消さない。画面の右上に小さなマイクの印、判定の状態、入力の大きさを出す。
- 録音したデータは判定に使うだけで、保存も送信もしない。リーダーが前面にないとき（`onPause`）はマイクを止める。

#### ライセンスとヘルプ

- ライセンス画面に、8.5 節の表のすべての依存のライセンス全文を出す。表示する内容はビルド時に生成する。
- 設定画面ができるまでは、ホームのメニューからライセンス画面を開く。
- ヘルプはアプリ内の操作ガイドだけとし、外部のページを開かない。
- 「このアプリについて」に、版、ビルドの日付、ライセンス画面への入口、この版の変更点を出す。変更点はアプリに同梱した文から出す。

### 5.3 先読みの方針

先読みは 3 層で行う。

| 層 | 内容 | 進む向き（既定） | 戻る向き（既定） |
|---|---|---|---|
| 準備済みのビュー | 表示サイズに縮小し、トリミングと補正を済ませた画像。`Half` のビューも半分ずつ用意する | 2 ビュー | 1 ビュー |
| ページの形 | 寸法だけ。組み方を決めるために先に読む | 4 ページ | 2 ページ |
| 元データ | エントリのバイト列（画像ファイルとしての符号化されたデータ）をメモリに持つ | 32 ページ | 16 ページ |
| SMB の先読み | エントリのバイト列をキャッシュディレクトリに書く | 50 ページ | 50 ページ |

- 元データの層は予算の半分までとし、入らない分は遠い方から減らす。
- 直近の 2 回のめくりがどちらも戻る向きなら、進む向きと戻る向きの枚数を入れ替える。
- 優先順位は、現在のビュー、次のビュー（次の 2 ページ）、前のビュー、の順とする。その先は、進む向きと戻る向きを枚数の比（既定 2:1）で交互に進める。形は、そのビューを準備する前に読む。
- 枚数は現在のビューの外側から数える。形の分からないページを含むビューは準備せず、形が分かって組み直した後の計画で準備する。
- 準備済みのビューと元データを合わせて予算に収める。現在のビューの分は先に確保する。
- 設定画面とページパネルのサムネイルの帯を出している間は、先読みを止める。現在のビューは読み込み、すでに持っているものは捨てない。
- ページを指定して移動したら、新しい範囲に入らない仕事をすべて取り消す。
- 表示中のビューは追い出さない。

メモリ予算は次の式で決め、設定には出さない。

```
budget = clamp(memoryClass × 1.5, 96 MB, 512 MB)
budget = min(budget, totalMem / 10)
isLowRamDevice なら budget = min(budget, 64 MB)、準備済みのビューは進む向き 1 つにする
```

- API 26 以降、Bitmap の画素はネイティブヒープに置かれ、`memoryClass` の制限を直接は受けない。そのため `memoryClass` は端末の格を表す目安として使い、端末の総メモリ（`ActivityManager.MemoryInfo.totalMem`）で上限を掛ける (要検証)。
- `onTrimMemory` で `TRIM_MEMORY_RUNNING_LOW` 以上を受けたら、現在のビュー以外の準備済みビューと元データを捨てる。
- 予算に既定の枚数が入らないときは、遠い方から枚数を減らす。

縮小の品質の要件は次のとおり。

- スクリーントーンの網点でモアレが出ないように、縮小率が 2 倍を超える部分は面積平均に近いフィルタで縮める。最後の 2 倍未満の部分だけを双一次か双三次で縮める。
- M1 では、デコーダの縮小と半分ずつの段階的縮小を組み合わせる。JPEG の DCT 段階の縮小（1/8 まで）と libwebp の縮小は面積平均に近いので、その範囲の 2 の累乗の縮小率をデコーダに任せる。PNG のデコーダの縮小は画素の間引きなので、PNG は元の大きさでデコードする。デコードの後は、2 倍以上の縮小が残る間は双一次フィルタで縦横をちょうど半分にする。半分ちょうどの双一次は 2 × 2 の平均と同じになる。最後の 2 倍未満を双一次で縮める。
- 予算に収まらず縮小率を上げて間引きになったときは、モアレが出うる。libwebp の縮小が面積平均であることと、この方法の品質と時間は、網点のテスト画像で確かめる (要検証)。ミップマップを使う GPU 描画と自前のボックスフィルタは、その結果が足りないときに試す。

## 6. 安定性と品質の要件

### 6.1 落ちないことの範囲

| 失敗の種類 | 要件 |
|---|---|
| 入出力、書庫、デコーダが投げる例外 | 読み込み層の境界で捕まえ、`PageResult` に変換する。未捕捉の例外ハンドラまで届かせない |
| `OutOfMemoryError` | デコードの境界で捕まえ、先読みを捨てて縮小率を上げて 1 回だけ再試行する。だめなら `Failed(ReadError, retryable = true)` にする。M1 の読み込み層は縮小率を 2 倍にして再試行するだけで、先読みを捨てるのはリーダーの先読みの計画が行う。ページのバイト列を読む段階で起きたものは縮小のしようがないので、再試行せずに `Failed(ReadError, retryable = true)` にする。本を開く途中で起きたものは、開けなかった理由を読み込みの失敗にする |
| ネイティブのライブラリが返すエラー | エラーコードを `PageResult` に変換する。自前の JNI コードは `abort()` を呼ばず、C++ の例外を JNI の境界の外へ出さず、JNI 呼び出しのたびに保留中の例外を確かめる |
| 不正な寸法やサイズの宣言 | 割り当ての前に 3.7 節の上限で止める |
| 第三者のネイティブコードの不正なメモリアクセス（SIGSEGV など） | プロセス内では `PageResult` に変換できない。fuzz と、ASan と HWASan でのビルド、ライブラリの更新、Q5 のプロセス分離で減らす。落ちた入力は修正後にコーパスに加え、回帰試験にする |
| 落ちた本を再び開くこと | 本を開く前に「開いている本」を記録し、最初のページを描いたら消す。記録が残ったまま起動したら、その本を自動では開かず、開くかどうかを尋ねる |

### 6.2 試験

| 種類 | 対象 | 実行 |
|---|---|---|
| 単体試験（JVM） | `layoutViews` と `scrollStops` のプロパティテスト、自然順、文字コードの判定、青空文庫記法の解析、設定の読み込みの検証 | すべての変更で CI |
| コーパス試験（端末） | コーパスの全ファイルを開き、全ページを読む。各ページが 10 秒以内に `PageResult` を返し、プロセスが生き残ること。各ファイルの期待する結果を目録に書き、照合する | API 28、API 31、最新 API のエミュレータと実機 1 台。マージ前と毎晩 |
| ネイティブの fuzz | 自前の JNI と libarchive の読み込み、libjxl、libavif の入口。libFuzzer と ASan、UBSan でホスト向けにビルドする。シードはコーパスから取る | 毎晩 1 時間。新しい落ち方で CI を失敗にする |
| Kotlin の fuzz | ZIP の名前の判定、青空文庫記法の解析、設定ファイルの読み込み。Jazzer を使う | 毎晩 |
| 画面の試験 | テキストの組版の結果画像の照合、主要画面のスクリーンショット | すべての変更で CI |
| モンキー試験 | 標準コーパスとエラーコーパスを開いた状態で `monkey` を 10,000 イベント | 毎晩 |

コーパスは生成スクリプト（`tools/corpus`）で決定的に作る。第三者のファイルは、ライセンスが許す場合だけ入れる。漫画の実ページは入れず、生成した画像を使う。画像は網点に似た模様にし、縮小のモアレが見えるようにする。

- 期待する結果の目録は 2 つある。`expected.tsv` は書庫の層（エントリの一覧と各エントリのバイト列）の結果、`pages.tsv` は本を開く層（ページの一覧と各ページの `PageResult`）の結果である。
- 標準コーパス（5.1 節）は約 350 MB になるので、端末の試験が持つコーパスには入れない。`./gradlew :tools:corpus:generateStandardCorpus` で `tools/corpus/build/standard-corpus/standard.zip` に作る。網点に乱数の雑音を足し、JPEG の品質 0.6 で 1 枚を約 1.5 MB にする（単ページは 1.2〜1.8 MB に入ることを試験で確かめる）。

コーパスには少なくとも次のものを入れる。

- **書庫**。任意の位置で切れたもの、ZIP64、4 GB を超える ZIP（疎ファイルで生成する）、データディスクリプタ付きの無圧縮と Deflate、65,535 バイトのコメント、前置データ付き、CP932 と UTF-8 の名前（UTF-8 フラグの有無）、不正なバイトを含む名前、RAR 4 と RAR 5（solid と非 solid、暗号化、ヘッダの暗号化）、7z の solid、tar、空の書庫、画像が 1 枚もない書庫
- **画像**。拡張子と中身が違うもの、ゼロで埋まったもの、途中で切れたプログレッシブ JPEG、CMYK、12 ビット JPEG、パレットと tRNS の PNG、16 ビット PNG、インターレース PNG、グレースケールとアルファ、65,535 × 65,535 を宣言する小さなファイル、1 × 1、幅 800 で高さ 50,000 の縦長画像、アニメーション WebP と GIF、HEIF、AVIF、JPEG XL、BMP の各ビット深度
- **PDF**。壊れたもの、パスワード付き、ページの大きさが混在するもの
- **テキスト**。CP932、UTF-8（BOM の有無）、UTF-16、EUC-JP、不正なバイトを含むもの、10 MB のもの

### 6.3 StrictMode

- デバッグビルドで有効にする。
- `ThreadPolicy` はメインスレッドでのディスクとネットワークの操作を検出し、プロセスを止める。
- `VmPolicy` は閉じ忘れた `Closeable`、Activity のリーク、許可のない content URI の利用、安全でない Intent の起動を検出し、ログに出す。CI のコーパス試験はこのログを数え、1 件でもあれば失敗にする。

### 6.4 ANR を起こさない

- メインスレッドでは入出力をしない。SAF のクエリ、SMB、Room、DataStore、書庫、デコードはすべて 8.3 節のディスパッチャで行う。
- ドキュメントプロバイダへの Binder 呼び出しもメインスレッドから行わない。
- モンキー試験とコーパス試験で、ANR が 0 件であることを確かめる。

### 6.5 SMB の接続が切れたときの回復

1. 読み込みで通信の例外が出たら、その接続を「切断」とする。読み込み中だったページは `Failed(ConnectionLost, retryable = true)` にする。
2. 0.5 s、1 s、2 s、4 s の間隔で最大 4 回、再接続する。
3. 4 回とも失敗したら、ネットワークの変化（`ConnectivityManager` のコールバック）か、ユーザーの再試行を待つ。
4. 再接続したら、開いていたファイルを開き直し、現在の位置から先読みをやり直す。先読みの範囲にある `ConnectionLost` のページは 1 回だけ自動で再試行する。

- 切断中も、準備済みのビューと元データのあるページは読める。
- 再試行の回数には上限があり、再帰で再試行しない。
- 接続のタイムアウトは 5 s、読み込みのタイムアウトは 15 s とする (要検証)。

### 6.6 ログ

- パスワード、ユーザー名、資格情報を含む URI をログに出さない。リリースビルドではファイル名とパスもログに出さない。
- CI に、試験中の logcat から試験用のパスワードを探す検査を置く。

### 6.7 アクセシビリティ

- ライブラリと設定の画面は TalkBack で操作できる。タッチ領域は 48 dp 以上にする。
- リーダーは、現在のページ番号を TalkBack に読み上げさせる。

- 自動バックアップの範囲は `dataExtractionRules` で指定する。
- 全体の設定は、DataStore に kotlinx.serialization の JSON の直列化を組み合わせて保存する。Proto DataStore にしないのは、protoc とその Gradle プラグインをビルドに加えずに済み、4.11 節の書き出しと同じ JSON の形と規則を使えるからである。
- 設定のファイルのキーは 4.10 節の内部名、列挙の値は列挙子の名前とする。知らないキーは無視し、欠けたキーと知らない列挙の値は既定値にし、範囲の外の整数は許される値のうち最も近いものに丸める。JSON として読めないファイルは既定値で置き換える。
- Keystore の鍵は端末の外に出せない。端末を移ると SMB のパスワードは入力し直しになる。
- 資格情報は、DB の主キー、`BookId`、URI、ショートカット、ログのどこにも入れない。

ネットワークと権限の方針は次のとおり。

| 権限 | 用途 | 要求の時期 |
|---|---|---|
| `INTERNET` | ユーザーが登録した SMB サーバーへの接続だけ | インストール時 |
| `ACCESS_NETWORK_STATE` | SMB の再接続の契機を知る | インストール時 |
| `RECORD_AUDIO` | 息での操作（M6） | 機能をオンにするとき |
| ローカルネットワークへのアクセスの権限 | 新しい targetSdk で LAN 内の SMB に接続するのに必要になる可能性がある (要検証) | Q14 |

- ストレージの権限は要求しない。ファイルは SAF だけで読む。
- 利用状況の収集、クラッシュの送信、広告、更新の確認、書体のダウンロードなど、SMB 以外の通信をしない。
- 依存の審査で、通信を行う依存が smbj だけであることを確かめる。

### 8.3 スレッドモデル

| 実行先 | 定義 | 仕事 |
|---|---|---|
| メイン | `Dispatchers.Main` | UI だけ |
| 入出力 | `Dispatchers.IO` | SAF、Room、DataStore |
| SMB | サーバーごとに `Dispatchers.IO.limitedParallelism(4)` | SMB の読み込み |
| デコード | `Dispatchers.Default.limitedParallelism(n)` | デコード、縮小、トリミング |
| 書庫のセッション | セッションごとに 1 本のスレッドに閉じ込める | libarchive の呼び出し |
| PDF のセッション | 文書ごとに 1 本のスレッドに閉じ込める | `PdfRenderer` の呼び出し |

- デコードの並列数 n は `clamp(availableProcessors − 2, 1, 4)` とする。メモリ予算が 128 MB 未満なら 1 にする。1 回のデコードが数十 MB を使うことがあるので、並列数でメモリの最大使用量を抑える。
- 先読みの計画は、開いている本ごとに 1 つのコルーチンで行う。ビューの変化を受け取って仕事の一覧を作り直し、要らなくなった仕事は構造化された並行性で取り消す。
- 取り消しはネイティブ側にも伝える。libarchive の読み込みコールバックと、libjxl と libavif のデコードのループは、セッションごとの取り消しフラグを確かめる。`ImageDecoder` はデコードの途中で止められないので、ヘッダの段階で取り消しを確かめ、それ以降は終わるのを待って結果を捨てる。
- 描画は準備済みの画像を描くだけで、描画のスレッドでデコードしない。
- リーダーの状態は不変のデータクラスとし、操作のイベントから縮約関数で次の状態を作る。

### 8.4 リーダーの描画面の決め方

M1 の最初に 2 つの試作を作り、計測で決める。

| 案 | 内容 |
|---|---|
| A | Compose の `Canvas` に `ImageBitmap` を描き、移動と拡大は `graphicsLayer` で行う |
| B | 独自の `View` の `onDraw` で描き、移動と拡大は `RenderNode` で行う |

- **計測するもの**。P1 と P2 の値、ピンチ中の落ちたフレーム、準備済みのビューの GPU へのアップロード時間。

- **判定**。P1 と P2 を満たす案のうち、単純な方を選ぶ。両方満たせば A を選ぶ。どちらも満たさなければ、`SurfaceView` と専用の描画スレッドの案 C を試す。
- 結果の数値と判断は `docs/` に記録する。
- **現在の判断**。暫定で A とする。試作、計測の方法、エミュレータでの数値、実機で計り直すコマンドは [q1-render-surface.md](q1-render-surface.md) にある。エミュレータの数値は判定に使えないので、実機で計り直して確定する (要検証)。

- `COPYING` は著作権者の欄がひな形のままで、各ファイルの著作権者が載っていない。そのためライセンス画面では、ネイティブの依存について 3 つを並べる。`license_file` の全文、ソースから抜き出した著作権の行（ビルド時に生成する）、目録の SPDX 識別子ごとの正規の全文である。

方針は次のとおり。

- 新しい依存は、推移的な依存とネイティブの依存を含めて、マージの前にライセンスを確かめ、この表に記録する。
- 配布物に入れてよいライセンスは、Apache-2.0、MIT、BSD-2-Clause、BSD-3-Clause、ISC、Zlib、0BSD、bzip2-1.0.6、Unicode-3.0、書体だけ OFL-1.1 とする。
- 使わないライセンスは、GPL（全版）、LGPL、AGPL、SSPL、RAR の公式展開ソースに付く非 OSI のライセンス、そのほかライセンスが不明なものである。
- GPL 系のソースから移したコードや、そのアルゴリズムの書き写しも入れない。
- 二重ライセンスの依存は寛容な側を選び、選んだ側を表に書く。
- Maven の依存は Licensee で検査し、許可リストの外のライセンスでビルドを失敗にする。
- ネイティブの依存は `third_party/manifest.toml` に名前、版、取得元の URL、SHA-256、SPDX 識別子を書く。CI のスクリプトで、`third_party/` の下のすべてのディレクトリが目録に載り、ライセンスファイルを持つことを確かめる。
- ライセンス画面の内容は、Licensee の出力と `third_party/manifest.toml` からビルド時に生成する。Maven の依存には、SPDX 識別子ごとの正規の全文（`build-logic/spdx/<識別子>.txt`）を付ける。全文のない識別子が出てきたらビルドを失敗にする。ネイティブの依存には、目録の `license_file` の全文を付ける。著作権の表示はこちらに含まれる。

**内容**。RAR 4 と RAR 5、7z、tar、solid と展開キャッシュ、PDF、GIF、BMP、HEIF、AVIF、JPEG XL、エントリ名の文字コードの判定と手動の変更、暗号化の検出、縦長画像のタイル表示、fuzz の毎晩の実行。

完了条件:

- 全コーパスで、各ファイルの結果が目録の期待と一致する。
- fuzz を延べ 24 時間回して、未修正の落ち方がない。
- 幅 800 で高さ 50,000 の画像を最後までスクロールでき、メモリが P10 に収まる。
- コーパスの CP932 と UTF-8 の名前が正しく表示され、文字コードを変えると並びが変わる。
- 3.3 節の libarchive に関する (要検証) がすべて解消している。

### M4 SMB

**内容**。サーバーの登録、Keystore での資格情報の保存、閲覧、先読み付きの読み込み、再接続、端末への保存、SMB 上のサムネイル、PDF の proxy file descriptor。

完了条件:

- 基準 NAS で P4 の SMB の目標を満たす。
- 読書中に Wi-Fi を切ると「再接続しています」が出て、アプリは終了しない。準備済みのページは読める。Wi-Fi を戻すと自動で再接続する。
- 試験用のパスワードが、logcat、DB の平文、書き出したファイルのどれにも現れないことを、自動試験で確かめる。
- サーバーのパスワードを変えても、既読の情報が残る。

### M5 テキストリーダー

**内容**。文字コードの判定、青空文庫記法の解析、縦書きの組版、ページ分割、ルビ、書体の取り込み、検索、目次、しおり、テキストの設定。

完了条件:

- 記法ごとの試験用テキストの組版の結果が、照合用の画像と一致する。
- P9 を満たす。
- 文字の大きさを変えても、変える前と同じ文が画面にある。
- 書庫の中のテキストと挿絵を開ける。

### M6 残りのリーダー機能と仕上げ

**内容**。ルーペ、余白トリミング、画像補正、回転、自動再生、息での操作、ページの共有、範囲を選んで表紙にする画面、操作ガイド、縦の連続スクロール（Q15 で採用したとき）、アクセシビリティの点検、Baseline Profile の調整、低位の確認端末での点検。

完了条件:

- 余白トリミングの試験画像で、切りすぎを防ぐ 4.8 節の規則がすべて働く。
- 息での操作は既定でオフであり、オンにするときだけ `RECORD_AUDIO` を求める。静かな部屋で短く 10 回吹くと 9 回以上めくれる (要検証)。リーダーが背面に回るとマイクが止まる。
- モンキー試験で、落ちる回数と ANR がともに 0 件である。
- この文書の (要検証) がすべて解消しているか、課題として登録されている。
